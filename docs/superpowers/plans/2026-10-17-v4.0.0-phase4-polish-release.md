# v4.0.0 Phase 4: Streaming, Quips, Cost, Netrunner Skin + Release Prep Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Finish v4.0.0 in five parts:
- **Streaming:** one long-lived `purrgotchi serve` process per session replaces the per-second `frame` spawns.
- **Quips:** kitten quips can come from the session's own model, with no API key.
- **Cost:** the lifetime cost tally moves to `session.measure`.
- **Skin:** the plugin ships the Netrunner theme and an opt-in Netrunner restyle (including skin-only mode).
- **Release:** the version goes to 4.0.0, with README and CHANGELOG ready for the coordinator to tag.

**Architecture:**
- **`serve`** is the `frame` loop inside one process. It writes NDJSON to stdout, ignores stdin EOF (`$.process.spawn` closes stdin at once), and exits on a broken pipe. The mod buffers chunks, splits them on `\n`, respawns `serve` when its arguments change (width, context bucket) or it dies, and falls back to Phase 3's polling ticker if `serve` keeps failing.
- **Quips and cost** reuse Phase 0's `quip-prompt`, `quip-store` and `cost` commands.
- **The skin** is pure `ui.render` rewriting that is gated per surface and always falls back to `next(e)`.

**Tech Stack:** Rust 2024 (one new command, no new dependencies), Claude Code 2.1.302 mods API (`$.process.spawn`, `$.model.complete`, `session.measure`, `turn.complete`, `ui.render` on `Spinner`, `UserMessage`, `ToolUse`, plugin `themes/`), `claude plugin test`.

**Spec:** `docs/superpowers/specs/2026-10-17-v4.0.0-claude-code-mod-design.md` §4.3 (`serve`), §4.5 (cost), §4.6 (quips), §4.7 (install, README), §4.9, §4.11, §5 row 4. **Overrides:** `docs/superpowers/plans/2026-10-17-v4.0.0-mods-api-findings.md` (§2 `spawn`, `model.complete`, themes, ToolUse props; §6 items 7, 11, 12). **Builds on:** Phases 0–3b (`…-phase0-json-surface.md`, `…-phase1-mod-skeleton-hooks.md` whose Global Constraints apply verbatim, `…-phase2-…`, `…-phase3-…`, `…-phase3b-…`).

## Global Constraints

All of Phase 1's Global Constraints apply, plus:

- **`$.process.spawn({ argv, cwd?, env?, input? })`** returns `HookStream<{ stream: 'stdout' | 'stderr'; text }, { code, signal }>`. Chunks are **raw text, not lines**. stdin gets `input` and is then closed, or is closed from the start when there is no `input`. The child dies when the `for await` loop ends, on `return()`, when `next.signal` aborts, or on module unload or hot reload. All spawning goes through `binary.ts`, which gains `spawnLines`.
- **`$.model.complete(...)`** always resolves (`isAnswered: false` on failure) and rejects only when the engine refuses to send. Use `model: 'haiku'` (alias), a short `maxTokens`, and keep the probability gate. It spends the user's own usage.
- **The theme id is `custom:purrgotchi:netrunner`** (prefixed with the plugin name). `themes/` is auto-discovered, and override keys that don't exist in the base palette are **silently dropped**. Never force the theme: the user picks it in `/theme`.
- **`ToolUse` has no `isExpanded`.** Only `UserMessage` and `ToolGroup` have it. A `ToolUse` restyle must never hide the tool's output.
- **Restyle hooks:** each one branches on `e.surface`. Any surface or props shape the hook doesn't recognise returns `next(e)`.
- **Classic path stays intact:** `install.sh`, the statusline and the Rust LLM providers are not deleted or changed (spec §4.6: "don't delete them in v4").

**Deviations from spec (intentional):**
- §4.3 "the child must exit when stdin closes": inverted. `serve` must **ignore** stdin EOF and exits only on SIGTERM/SIGKILL (from the engine) or a stdout write error (the parent is gone).
- §4.6 quips default: `quips` stays `own-key` by default in v4.0.0 (spec table), and `session-model` is opt-in. The probability gate is `QUIP_PROBABILITY = 1/5`, which mirrors `hooks.rs` `REACT_DICE_DENOM = 5`. It is applied in the mod, because `quip-prompt` has no dice.
- §4.7 `/plugin install purrgotchi --marketplace Englader/purrgotchi`: the real 2.1.302 syntax is `/plugin marketplace add Englader/purrgotchi` then `/plugin install purrgotchi@purrgotchi` (CLI: `claude plugin marketplace add …`, `claude plugin install purrgotchi@purrgotchi`).
- §3.2 minimum version: no semver floor. The Phase 1 capability handshake remains the contract.

## Review Focus

1. **`serve` lifecycle across hot reload, `/clear` and resize.** Exactly one live `serve` child per session at any moment: no orphan after reload (the engine kills it on unload; the new runtime spawns one), no stop on `/clear` (`session.end` reason `clear`), and one respawn per width change after a 500 ms debounce, not one per render. Pinned in Task 4.2.
2. **An old binary without `serve`.** It exits 2 at once. After 3 exits within 60 s the mod falls back to polling `frame`, without a respawn storm or a toast. Pinned in Task 4.2 (`falls back to polling after 3 quick exits`).
3. **Partial and merged NDJSON chunks.** A frame split across two chunks, two frames in one chunk, a trailing partial line at exit, or a non-JSON line (stderr noise on stdout). Expected: every complete line is applied once, the partial line is discarded, and garbage is skipped. Pinned in Task 4.2 (`splitLines` table).
4. **Quip failure modes.** `model.complete` not answered, an empty reply, a reply with control characters or more than 500 characters, `quip-store` rejecting an empty-after-sanitize quip, or a subagent's / aborted / refused `turn.complete`. Expected: no toast, no model call for subagents/aborts, and the text stored is only what the binary sanitized. Pinned in Task 4.4.
5. **Skin-only mode on a machine without the binary** (`layout: off`, `restyle: true`). No `process.run` or `spawn` ever runs, no "binary not found" toast appears, and the restyle hooks work on terminal, desktop and mobile. Pinned in Task 4.5.

### Task 4.1: Rust: `purrgotchi serve` (NDJSON frame stream)

**Model:** sonnet

**Files:**
- Modify: `rust/src/frame.rs`, `rust/src/main.rs`
- Create: `rust/tests/json_serve.rs`

**Interfaces:**
- Consumes: `frame::{FrameOpts, parse_opts, build}`, `statusline::{kitten_view, advance}`, `json::{print, no_kitten}`.
- Produces: `frame::render_once(opts: &FrameOpts) -> Result<FrameJson, ()>`. `Err(())` means no kitten. It contains the body of today's `frame::run` (view, optional advance, JSON build) and **does not print**. `frame::run` becomes "`render_once` → print or `no_kitten` → exit code", with byte-identical output (the Phase 0 frame tests must pass unchanged).
- Produces: `frame::serve(opts: &FrameOpts, interval_ms: u64) -> i32`. It loops forever:
  - Run `render_once`. `Ok(j)` prints one line of `serde_json::to_string(&j)`. `Err` prints one `ErrorJson` `no_kitten` line (the kitten may hatch later, so keep looping).
  - Write through a locked `stdout` with `writeln!` and then `flush()`. **On any write or flush error, return 0.** Never `println!`: with `panic = "abort"` in release, a panic on EPIPE would abort with a core dump instead of exiting quietly.
  - Then sleep `interval_ms`.
  - **Never read stdin.**
- Produces: the `main.rs` arm `"serve"`. It parses with `frame::parse_opts(&args)` (same flags as `frame`: `--width`, `--context-pct`, `--advance`, `--pixels`, `--tick` ignored) plus `--interval-ms N`, which must be an integer clamped to `[250, 60000]` with default `1000`. A non-integer value gives exit 2 with the usage line `usage: purrgotchi serve [--interval-ms N] [--width N] [--context-pct P] [--advance] [--pixels]`. Add `serve` to the global usage line.

### Task 4.2: Mod: `ServeSource` with respawn, debounce and polling fallback

**Model:** opus (stream lifetime, respawn and fallback)

**Files:**
- Create: `mod/hooks/serve.ts`
- Modify: `mod/hooks/binary.ts` (`spawnLines`, `splitLines`), `mod/hooks/ticker.ts`, `mod/hooks/runtime.ts`, `mod/hooks/session.ts`, `mod/hooks/testkit.ts` (`process.spawn` answer that yields scripted chunks)
- Test: `mod/hooks/serve.test.ts`

**Interfaces:**
- Produces: `splitLines(buffer: string, chunk: string): { lines: string[]; rest: string }`, a pure function.
- Produces: `spawnLines($, bin, args, onLine: (line: string) => void): { done: Promise<{ code: number | null; signal: string | null }>; stop(): void }`. It wraps `$.process.spawn({ argv: [bin, ...args] })`, consumes the stream in a detached async loop, ignores `stderr` chunks (except a debug log of the first 200 chars), and calls `onLine` per complete stdout line. `stop()` calls the stream's `return()`. It never throws: a rejected spawn resolves `done` with `{ code: null, signal: 'spawn-failed' }`.
- Produces: `serveArgv(o: { width: number; ctxPct: number | null; advance: boolean; pixels: boolean }, intervalMs = 1000): string[]`. It is `['serve', '--interval-ms', String(intervalMs), ...the frameArgv flags without 'frame' and '--json']`. Build both from one shared `frameFlags(o)` helper in `ticker.ts`.
- Produces: `ctxBucket(p: number | null): number`, which is `p == null ? 0 : Math.floor(p / 5) * 5`. Respawning on every 0.1 % change would thrash; mood thresholds are at 40 and 80, and a 5-point bucket keeps them exact while respawning at most about once per turn.
- Produces: `class ServeSource { constructor(rt: Runtime, apply: ($, line: string) => void); start($): void; argsChanged($): void; get broken(): boolean }`:
  - `start` spawns `serve` with `serveArgv(current)`. On `done`, if the source was not stopped deliberately, it records the exit time and respawns after `min(1000 * 2^k, 30000)` ms via `$.clock.after`.
  - **3 exits within 60 s** set `broken = true`, log once, and stop respawning.
  - `argsChanged` debounces 500 ms (a `$.clock.after` that resets on each call). If `serveArgv` actually differs from the running one, it stops the current child (deliberately) and spawns a new one.
- `ticker.ts` changes:
  - `FrameTicker.start` now prefers `ServeSource` when `tickIntervalMs(layout) === 1000` (dock/bottom) and `!rt.serveDisabled`. The clock path stays for `classic` (5 s status only) and as the fallback.
  - A 1 s `$.clock.every` **watchdog** checks `serve.broken`. When it is broken, the ticker switches to the Phase 3 polling interval (same `tick`).
  - Polling also runs while no serve line has arrived for 3 s (startup gap or a stalled child).
  - The shared `applyFrame($, rt, json: RunOutcome<FrameJson> | parsed line)` does what a Phase 3 tick result did: update `frameAtom`, `rt.kitten` and status, and handle `no_kitten`.
  - `poke` still runs one immediate `frame` (single-flight) for responsiveness after actions.
  - `rt.view` width changes (pane/band render) and `registerMeasure` context changes call `rt.ticker.argsChanged($)`. Never call it from a render hook: the render hook only records `rt.view`, and the 1 s watchdog compares `stripWidth(rt)` and `ctxBucket(rt.ctxPct)` with the running args and calls `argsChanged` when they differ.
- **Lifetime:** the serve loop is started from `onSessionStart` (an after-return `$` call, proven in Phase 1 Task 1.6).
  - If Task 1.6 recorded `AFTER-RETURN: KILLED`, set `rt.serveDisabled = true` (constant `SERVE_ENABLED = false` in `serve.ts`) and skip this source. Polling stays.
  - `session.end` never stops `serve` (`/clear`). A module unload kills it (engine).
