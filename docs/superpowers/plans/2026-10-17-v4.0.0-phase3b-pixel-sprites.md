# v4.0.0 Phase 3b: Generated Pixel Sprites Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The kitten in the pane and band becomes generated 32×32 pixel art in which breed, stage, mood, frame, rarity and shiny are all visible. It is drawn as a half-block `Raster` on the terminal and as an `Svg` on desktop/mobile. The classic statusline keeps its ASCII sprites, byte for byte.

**Architecture:**
- The prototype generator (`docs/superpowers/specs/assets/2026-10-17-sprites/sprite.mjs`) is ported to Rust (`rust/src/pixel.rs`), so the binary stays the single source of truth.
- `frame --json --pixels` adds a `pixels` grid (32 rows × 32 of `"#rrggbb"` or `null`).
- The mod only packs that grid for each surface (`mod/hooks/pixels.ts`) and swaps it into the pane and band, falling back to the ASCII sprite when `pixels` is absent.

**Tech Stack:** Rust 2024 (no new dependencies), Claude Code 2.1.302 `Raster` (terminal only: `{ key, columns, rows, cells: base64 }`, where each cell is a little-endian u32 triplet `[codePoint, fg, bg]`, a colour is `0x00RRGGBB` or `0x01000000` for the terminal default, and up to 1024 colour pairs are allowed) and `Svg` (desktop, vscode and mobile: `{ source ≤ 131072 chars, alt, width?, height? }`).

**Spec:** `docs/superpowers/specs/2026-10-17-v4.0.0-claude-code-mod-design.md` §4.8 (sprite system, drawing per surface, where the generator lives), §4.10 (dock 32×16 cells, bottom 32×10 crop), §5 row 3b. **Overrides:** `docs/superpowers/plans/2026-10-17-v4.0.0-mods-api-findings.md`. **Builds on:** Phase 0 (`frame`, `colors::Rgb`), Phase 1 (Global Constraints and File Map apply verbatim), and Phase 3 (`paneTree`, `registerBand`, `frameArgv`).

## Global Constraints

- **No JS↔Rust pixel parity requirement. Do not chase one.** JS `Math.round` rounds half toward +∞ while Rust's `f64::round` rounds half away from zero. The prototype's `hash` multiplies doubles past 2^53 before `|0`, which Rust integer math does not reproduce. `sin`, `atan2`, `hypot` and `powf` can differ by an ulp at threshold compares (`> -0.4`, `<= 1`). The PNGs in `docs/superpowers/specs/assets/2026-10-17-sprites/` are the **visual** reference only. The Rust generator's own output is pinned by its own snapshot hashes.
- **Port for fidelity of look, not bits.** Keep the prototype's structure (silhouette → traits → coat → lighting → outline/rim → collar → face → props → rarity/shiny) and its constants (stage geometry, breed table, palette, eye tables, glyphs). Use these helpers: `js_round(x) = (x + 0.5).floor()` wherever the prototype calls `Math.round` (it keeps shapes closest to the reference), and an `i32` `wrapping_mul` / `wrapping_add` FNV-style `hash(x, y, seed) -> f64` in `[0, 1)` with the prototype's constants.
- **The palette** is `colors.rs`'s, plus the prototype's art constants: `OUTLINE #160b26`, lid `#160b26`, shadow mix target `#0d0618`, rim cyan `#0abdc6` (left) and magenta `#ea00d9` (right), nose `#ff7aa8` and inner ear `#f39bb8`. Rarity eye/collar colours are common `#0abdc6`, uncommon `#57eca6`, rare `#b45cff`, epic `#ffc93c`, and legendary cycling `RAINBOW = [#ff5468,#ffc93c,#f3f31b,#57eca6,#0abdc6,#b45cff,#ea00d9]` by `tick % 7`.
- **Rarity comes from the state's `rarity` field, not from the breed.** It is always consistent with the breed (`identity::breeds_for_rarity`), and the name colour uses the same field.
- **Unknown inputs never panic.** An unknown breed falls back to `Ginger`'s table entry, an unknown stage to `adult`, and an unknown mood to `calm`.
- **The ASCII sprites (`sprites.rs`) and the statusline are untouched.** Pixel art exists only behind `frame --pixels`.

**Deviations from spec (intentional):**
- §4.8 "`frame --json` returns `{ "pixels": … }`": pixels are **opt-in via `--pixels`**, so the default `frame` stays small for the status-only ticker (`classic` layout) and older consumers. The wire form is fixed as nested arrays of `"#rrggbb" | null` (`pixels[y][x]`), not pre-packed base64. The mod packs per surface (terminal Raster vs SVG), and that packing is presentation, not game logic.
- §4.8 open art questions (side-view scene silhouettes; celebration effect layers): **out of scope for v4.0.0.** Scenes keep their ASCII strip under the pixel sprite, and celebrations keep their speech caption. They are listed as follow-ups in the Phase 4 CHANGELOG.
- `$.ui.blit` is not used. The ticker redraw at 1 Hz is cheap; blit is an optimisation for later.

## Review Focus

1. **Transparent-pixel half-blocks.** A cell whose top is transparent and bottom is coloured must not paint the top half in the terminal's default foreground. Use `▄` with fg = bottom; `▀` with fg = top and bg = bottom only when both are set; a space when both are transparent. Pinned in Task 3b.3 (`packRaster` cell table).
2. **Every breed, stage, mood, frame and shiny combination renders without panicking** and differs where it should: the legendary eye cycles with `tick`, shiny adds `#ffffff` sparkles, and the sleep `Z` appears only for `sleep`. Pinned in Task 3b.1 (snapshot + invariants).
3. **Old binary without `--pixels`.** Phase 0 `parse_opts` reads only the flags it knows, so a Phase-3 binary ignores `--pixels` and returns a frame with no `pixels` key. The pane must then fall back to the ASCII sprite. If some build does reject the flag with exit 2, the ticker drops the flag rather than losing the pane. Pinned in Task 3b.3 (`falls back to ASCII when pixels absent` + `retries without --pixels after exit 2`).
4. **SVG size cap.** The worst case (dense, noisy coat: Void Cat with starfield, Calico, shiny legendary) must stay under 131,072 characters. Pinned in Task 3b.3 (run-merged SVG size assertion on every fixture grid).
5. **Narrow surfaces.** Below 34 body columns there is no room for a 32-column sprite, so the ASCII sprite is used. Pinned in Task 3b.3.

### Task 3b.3: Mod: Raster and SVG renderers in the pane and band

**Model:** sonnet

**Files:**
- Create: `mod/hooks/pixels.ts`, `mod/hooks/fixtures/pixels.json`, `mod/scripts/record-pixel-fixtures.sh`
- Modify: `mod/types/index.d.ts` (`FrameJson.pixels?: (string | null)[][]`), `mod/hooks/ticker.ts` (`frameArgv` gains `pixels`), `mod/hooks/pane.tsx`, `mod/hooks/band.tsx`
- Test: `mod/hooks/pixels.test.ts`, `mod/hooks/pane.test.tsx` (new cases), `mod/hooks/band.test.tsx` (new cases)

**Interfaces:**
- Produces: `PixelGrid = (string | null)[][]`.
- Produces: `hexToU32(hex: string | null): number`. `null` gives `0x01000000` (terminal default). Otherwise it gives `0x00RRGGBB`.
- Produces: `packRaster(px: PixelGrid, r0 = 0, r1 = px.length): { columns: number; rows: number; cells: string }`. It emits one cell per (x, pair of rows `y`, `y+1`) for `y` from `r0` in steps of 2 up to `r1`, so `rows = ceil((r1 - r0) / 2)` and `columns = 32`. Each cell is three little-endian u32 values, and `cells` is the base64 of the bytes:

| top | bottom | codePoint | fg | bg |
|---|---|---|---|---|
| set | set | `0x2580` `▀` | top | bottom |
| set | null | `0x2580` `▀` | top | `0x01000000` |
| null | set | `0x2584` `▄` | bottom | `0x01000000` |
| null | null | `0x20` space | `0x01000000` | `0x01000000` |

- Produces: `base64(bytes: Uint8Array): string`, a hand-rolled RFC 4648 encoder with padding. It does not depend on `Buffer` or `btoa` being present in the mod runtime.
- Produces: `cropRows(px: PixelGrid, height = 20): [number, number]`. It starts at the first row containing any non-null pixel, or 0 if none. The window is `[start, start + height)`, shifted up so it never passes 32. The band portrait (32×10 cells) uses it.
- Produces: `svgSource(px: PixelGrid, r0 = 0, r1 = px.length): string`, which gives `<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 {r0} 32 {r1-r0}" shape-rendering="crispEdges">` with one `<rect x y width height="1" fill>` per **horizontal run** of equal colour (null skipped).
- Produces: `spriteElement(els, surface: string, frame: FrameJson, mode: 'full' | 'portrait', cols: number): RenderElement`:
  - No `frame.pixels`, or `cols < 34`: ASCII via `renderLines(els, frame.sprite)`.
  - `surface === 'terminal'`: `<Raster key={mode === 'full' ? 'kitten-full' : 'kitten-portrait'} columns={32} rows={16 | 10} cells={…} />`.
  - `desktop`, `vscode`, `mobile`: `<Svg source={svgSource(...)} alt={`${frame.name} the ${frame.breed}`} width={…} height={…} />`. Pick the width/height units from the d.ts `SvgProps` doc (grep `export type SvgProps`).
  - Any other surface: ASCII.
- `frameArgv` gains `pixels: boolean`. `FrameTicker` passes `pixels: layout === 'dock' || layout === 'bottom'` and appends `'--pixels'`.
  - **Old-binary guard:** if a tick with `--pixels` comes back `failed` with exit code 2 and stdout is empty, set `rt.noPixels = true` and drop the flag from then on. Add `noPixels: boolean` to `Runtime`.
- `paneTree` uses `spriteElement(..., 'full', cols)` in place of the ASCII sprite. `registerBand`'s portrait column uses `spriteElement(..., 'portrait', 32)` with `cropRows`.
