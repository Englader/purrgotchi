# v3.6.0 Phase 4 — Provider-agnostic LLM Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

> **Testing note:** During implementation and verification of this phase we will use **Gemini** as the active provider, because the active Anthropic API key has zero credit. Gemini's free tier is sufficient for all manual smoke tests. The Anthropic provider stays first-class and is verified by code review + unit tests, with live verification deferred to whenever credit becomes available.

**Goal:** Make the v3.5.0 LLM features (L1 react worker, L5 hatch personality blurb) provider-agnostic. Users select a provider explicitly via `PURR_LLM_PROVIDER` and supply the matching `*_API_KEY`. Three providers ship in v1: Anthropic, Gemini, OpenAI. A repo-root `.env` file is auto-loaded so users don't need to `export` keys per shell.

**Architecture:** Introduce a `LlmProvider` trait in a new `rust/src/llm/` module tree. Refactor the existing `llm.rs` HTTP code into `llm/anthropic.rs` implementing the trait. Add `llm/gemini.rs` and `llm/openai.rs` siblings. A thin `llm/select.rs` reads `PURR_LLM_PROVIDER` and dispatches to the right impl. Call sites (`react.rs`, `hatch.rs`) move from concrete `call_haiku()` to `select::current_provider()?.complete(req)`. A `dotenvy` call at `main.rs` entry loads `./.env` if present, before any env-var reads.

**Tech Stack:** Rust 2024, existing serde + ureq + rustls. New dep: `dotenvy` (well-maintained, zero deps, MIT). Bin-only crate (use `cargo test`, never `--lib`). Repo at `rust/`.

**Breaking change:** Existing `ANTHROPIC_API_KEY`-only users will lose LLM features on upgrade until they set `PURR_LLM_PROVIDER=anthropic`. Documented loudly in CHANGELOG.

## Locked types and constants

```rust
// llm/mod.rs
pub struct LlmRequest {
    pub system: String,
    pub user: String,
    pub max_tokens: u32,
}

pub struct LlmResponse {
    pub text: String,
    pub input_tokens: u32,
    pub output_tokens: u32,
    pub model: String,
    pub latency_ms: u128,
}

pub enum LlmError {
    AuthMissing,                        // *_API_KEY unset
    Http(u16, String),                  // status + truncated body for diagnostics
    Network(String),
    Timeout,
    MalformedResponse(String),
}

pub trait LlmProvider {
    fn name(&self) -> &'static str;     // "anthropic" | "gemini" | "openai"
    fn complete(&self, req: LlmRequest) -> Result<LlmResponse, LlmError>;
}

// llm/select.rs
pub enum ConfigError {
    ProviderNotSet,                     // PURR_LLM_PROVIDER missing
    UnknownProvider(String),
}

// Defaults (overridable via PURR_LLM_MODEL)
const ANTHROPIC_DEFAULT_MODEL: &str = "claude-haiku-4-5";
const GEMINI_DEFAULT_MODEL: &str = "gemini-2.5-flash";
const OPENAI_DEFAULT_MODEL: &str = "gpt-4o-mini";

// Endpoints
const ANTHROPIC_URL: &str = "https://api.anthropic.com/v1/messages";
const GEMINI_URL_FMT: &str = "https://generativelanguage.googleapis.com/v1beta/models/{model}:generateContent";
const OPENAI_URL: &str = "https://api.openai.com/v1/chat/completions";

const HTTP_CONNECT_TIMEOUT_SECS: u64 = 10;
const HTTP_READ_TIMEOUT_SECS: u64 = 10;
```

**Selection rules (locked):**
1. `PURR_LLM_PROVIDER` MUST be set. If missing → `ConfigError::ProviderNotSet` → silent static fallback (same as current no-key path).
2. Value must be one of `anthropic | gemini | openai` (lowercased). Any other → `ConfigError::UnknownProvider`.
3. The selected provider's `*_API_KEY` MUST be set. Missing → `LlmError::AuthMissing` → silent static fallback.
4. `PURR_LLM_MODEL` is provider-scoped: same env var, but the value is interpreted by whichever provider is active.

**Cost tracking:** Unchanged from v3.5.0. Anthropic provider continues to credit `lifetime_cost_usd`. Gemini and OpenAI providers do not contribute to the accumulator (documented as known limitation; users on free Gemini tier won't notice).

# OPENAI_API_KEY=sk-...
# PURR_LLM_MODEL=gpt-4o-mini

`.env` (each user creates locally, gitignored).

`dotenvy::dotenv()` loads from cwd. **Process-set env wins over `.env`** (standard dotenvy behavior). This is desirable: existing users with shell-exported `ANTHROPIC_API_KEY` keep working without touching `.env`.

### T5 — `llm/select.rs` dispatcher

**Tests first:**
- `current_provider()` with `PURR_LLM_PROVIDER=anthropic` → returns `Anthropic` impl
- Same for `gemini`, `openai`
- Missing var → `ConfigError::ProviderNotSet`
- Unknown value → `ConfigError::UnknownProvider("foo")`
- Case-insensitive match (`Anthropic`, `ANTHROPIC` all valid)
- `PURR_LLM_MODEL` reaches the selected provider's constructor
- Tests use `temp-env` crate or scoped env-var helpers to avoid global state pollution

**Implementation:**
```rust
pub fn current_provider() -> Result<Box<dyn LlmProvider>, ConfigError> {
    let provider = env::var("PURR_LLM_PROVIDER")
        .map_err(|_| ConfigError::ProviderNotSet)?;
    let model = env::var("PURR_LLM_MODEL").ok();
    match provider.to_lowercase().as_str() {
        "anthropic" => Ok(Box::new(Anthropic::new(model))),
        "gemini" => Ok(Box::new(Gemini::new(model))),
        "openai" => Ok(Box::new(OpenAi::new(model))),
        other => Err(ConfigError::UnknownProvider(other.to_string())),
    }
}
```

**Acceptance:** All branches covered, tests pass.

## Risks and mitigations

| Risk | Mitigation |
|---|---|
| User upgrades to v3.6.0 with shell-exported `ANTHROPIC_API_KEY` only — silent loss of LLM features | CHANGELOG breaking-change callout; debug log shows `ConfigError::ProviderNotSet` when `PURR_DEBUG=1` |
| Voice drift across providers makes quips feel inconsistent | Accepted by user; documented in plan, not a bug |
| `.env` accidentally committed despite `.gitignore` | `.env.example` only; `.gitignore` updated in T0; document in CHANGELOG |
| Gemini/OpenAI free tier hits rate limits during testing | Each provider has its own backoff handled at HTTP-error layer; treat 429 same as other 4xx (silent fallback) |
| New providers add ~20 transitive deps each | All three reuse the existing `ureq` HTTP client; no new HTTP deps needed |
| Trait abstraction leaks because Anthropic returns `usage.input_tokens` while OpenAI returns `usage.prompt_tokens` | Normalize at parse time inside each provider impl — `LlmResponse` has provider-neutral field names |

## Out of scope for v3.6.0

- Per-provider cost-tracking math (Anthropic-only stays)
- Per-provider prompt tuning (voice drift accepted)
- Provider auto-detect from which API key is set (user explicitly chose explicit-only)
- Streaming responses (none of the call sites need streaming)
- Retry-with-backoff (existing single-shot semantics preserved)
- AWS Bedrock, OpenRouter, Ollama (deferred to v3.7+)
