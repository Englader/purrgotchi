# Purrgotchi v4.2 Neon Grid Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a Neon Grid colour theme for all of Claude Code and redraw the six terminal UI pieces the mods API exposes (Spinner word, TurnDuration, PromptHint, SessionMode, InfoNotice, ToolProgress) in Neon Grid style. The HUD statusline and band cat stay exactly as they are.

**Architecture:** One pure module, `mod/hooks/neon.ts`, holds the palette, the 72-key theme map and every Neon Grid string and text function, so a later desktop project can copy it whole. Six small hook files (one per component) turn its output into either a `word` rewrite (Spinner) or a one-line `Text` tree, and they pass to the engine for anything they don't recognise or any non-terminal surface. `mod/themes/neon-grid.json` is generated from `neon.ts` by a Node script that also checks the key set against the Claude Code binary.

**Tech Stack:** Claude Code 2.1.302 mods API (TypeScript, `claude plugin test`, `tsc`, `claude plugin validate`). Node 24 (type-stripped `.ts` import) for the theme generator. Python 3 pty harness plus pyte for the live check. No Rust code changes.

## Gaps the spec left open, settled here

1. **Hint lines are mapped part by part, keys taken from the engine's text.** `PromptHint.hint` is one string, parts joined by single spaces ("read the way the screen reader reads it"). `parseHint` consumes it with a table of sticky regexes, each capturing the key the engine printed (`esc`, `ctrl+x`, a rebound chord). Every part must match a rule or the whole line passes. A drawn line therefore never shows a key the engine didn't. **No parts are added.** The spec's example `[ENTER] TRANSMIT [ESC] ABORT [/] COMMANDS [!] SHELL` is a mockup collage: the idle engine line is `? for shortcuts`, so the idle Neon line is `[?] SHORTCUTS`. Adding hints the engine doesn't show could lie under rebound keys (anti-goal "tell the truth about which key does what").
2. **Table source strings come from the binary, confirmed by a live props probe.** Task 1.1 runs a throwaway probe plugin that records every prop value the six components receive and writes them to a file. Each table rule must be either a literal in the 2.1.302 binary (`strings` grep) or seen in the probe corpus. The corpus is pinned as test cases.
3. **Draft-while-working and a set `tail` pass.** When `isDraft && isWorking`, built-in plugins (e.g. `cc-plugin-responsive-mode`) add a `tail` or `hint` from below our hook. A tree would drop their text, so PromptHint passes in that state and whenever `e.props.tail !== undefined`.
4. **Spinner word per turn, without state.** The engine samples `word` once per turn ("as sampled for this turn"), so `spinnerWord(engineWord)` picks from `SPINNER_WORDS` by FNV-1a hash of the engine word. That gives a new word each turn, never on a timer, and needs no hook outside the render. Consecutive turns can hash to the same word (1 in 10). Accepted. Only `word` is rewritten, so the engine's `…` suffix still follows `░▒▓` (the decision was "word only").
5. **InfoNotice keeps the engine's words.** The spec's example `NEURAL LINK ESTABLISHED // 3 HOOKS ARMED` would reword. The decision is "engine words kept", so the line is `▸ ` + the text uppercased, with the `/command` kept in its own case (a slash command typed in caps may not run).
6. **Theme ground.** A theme cannot paint the terminal background. In the dark base, `background` is an accent (`rgb(0,204,204)`), not the ground. The violet ground `#0d0a14` is used for `inverseText` and `clawd_background`, and the README recommends it as the terminal's own background. Readability is checked against `#0d0a14`.
7. **Tree colours are raw hex from `PALETTE`**, not theme keys, so the pieces look Neon Grid under any theme and the palette stays the one source.
8. **"Each themed key lands" is checked statically for all 72 keys and sampled live.** The engine keeps an override only when `Object.hasOwn(basePalette, key)` and the value passes its validator (binary: `BZt`/`z5`). `theme.mjs --check` replays exactly that against the binary's `dark` palette. Live, pyte reads the RGB of the keys a short scripted session shows (Task 4.2 table). The other keys (rainbow, subagent colours, fast mode and so on) can't be put on screen on demand.

## Review Focus

1. **A hint line mixing known and unknown parts** (`? for shortcuts 2 background tasks`, a live pill, a new engine hint). It must pass whole, never half-redrawn. Owner: Task 2.3 (`mixed known and unknown parts pass`).
2. **Rebound keys.** The user binds interrupt to `ctrl+g` or background to `alt+b`. The redraw shows `[CTRL+G]` / `[ALT+B]`, never a hard-coded key. Owner: Task 1.2 (`parseHint keeps the engine's key`), Task 2.3 (`tool progress keeps a rebound key`).
3. **Another plugin's text on the hint line** (`tail` set above us, or the draft-while-working state where built-ins add it below us). It passes so their text survives. Owner: Task 2.3 (`tail or draft while working passes`).
4. **Spinner in a special state** (`message` set while compacting, an empty `word`, the desktop surface). It is untouched, or deterministic for `''`. Owner: Task 2.1.
5. **Duration edges and long text in a narrow terminal.** 59 999 ms must not print `60.0s`. Hours read `1h 2m`. A long notice or many modes stay on one truncated line. Owner: Task 1.2 (`durationText edges`), Task 2.2 (`trees truncate, never wrap`).

**Files:**
- Create: `mod/hooks/neon.ts`, `mod/hooks/neon.test.ts`

**Interfaces:**
- Consumes: the Task 1.1 corpus.
- Produces (`neon.ts`, no imports except `import type`, no `$`):
  - `export const PALETTE` (Task 1.3 fills it; this task adds only `magenta`, `cyan`, `yellow`, as `as const` hex strings)
  - `export const SPINNER_WORDS: readonly string[] = ['JACKING IN','DECRYPTING','SPOOFING ICE','REROUTING POWER','OVERCLOCKING','TRACING SIGNAL','COMPILING DAEMONS','SYNCING WETWARE','BREACHING FIREWALL','UPLOADING']`
  - `export const NEON = { spinner: ['▓▒░ ', ' ░▒▓'], turnFrame: '◢◤', turnLabel: 'EXECUTED IN', mode: ['⟦ ', ' ⟧'], notice: '▸ ', hintGap: '   ', background: 'SEND TO BACKGROUND' } as const`
  - `export function spinnerWord(engineWord: string): string`: `NEON.spinner[0] + SPINNER_WORDS[fnv1a(engineWord) % SPINNER_WORDS.length] + NEON.spinner[1]`. `fnv1a`: 32-bit FNV-1a over UTF-16 code units (`h = 0x811c9dc5; h ^= c; h = Math.imul(h, 0x01000193) >>> 0`), not exported.
  - `export function durationText(ms: number): string`:
    - under 60 000 ms (and for negative or NaN, treated as 0): `${(Math.floor(ms / 100) / 10).toFixed(1)}s`
    - under 3 600 000 ms: `${m}m ${s}s` (both floored)
    - otherwise: `${h}h ${m}m`
  - `export function turnText(ms: number): string` = `` `${NEON.turnLabel} ${durationText(ms)}` ``
  - `export type KeyHint = { key: string; word: string }` (`key` already uppercased, without brackets)
  - `export type HintRule = { re: RegExp; word: string }`: `re` is sticky (`y`) with exactly one capture group, the key.
  - `export const HINTS: readonly HintRule[]`. Longest-first. Initial rules, then pruned or extended per the Task 1.1 corpus (keep a rule only if it is a binary literal or in the corpus; a new action defaults to its own words uppercased):

    | engine part | `word` |
    |---|---|
    | `(\S+) for shortcuts` | `SHORTCUTS` |
    | `(\S+) for shell mode` | `SHELL MODE` |
    | `(\S+) to interrupt and send` | `ABORT + SEND` |
    | `(\S+) to interrupt` | `ABORT` |
    | `(\S+) to clear` | `CLEAR` |
    | `(\S+) to delete` | `DELETE` |
    | `(\S+) to stop` | `STOP` |
    | `(\S+) to find` | `FIND` |
    | `(\S+) to group` | `GROUP` |
    | `hold (\S+) to speak` | `HOLD TO SPEAK` |
    | `(\S+) to send` (only if in the corpus) | `TRANSMIT` |
  - `export function parseHint(hint: string): KeyHint[] | null`. The algorithm:
    ```
    s = hint.trim(); if s === '' → null
    i = 0; out = []
    while i < s.length:
      find the first rule whose re (lastIndex = i) matches AND whose match ends at s.length or before ' '
      none → return null
      out.push({ key: m[1].toUpperCase(), word: rule.word }); i = end of match
      skip one separator at i: ' · ' or ' '
    return out
    ```
  - `export const BACKGROUND_HINT = /^\((\S+) to run in background\)$/`
  - `export function parseBackgroundHint(hint: string): KeyHint | null` → `{ key: m[1].toUpperCase(), word: NEON.background }`
