# Purrgotchi v4.1 Cat Band Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move the pixel cat out of the statusline into Claude Code's `AbovePrompt` band. There it roams the full width at 30 fps and 3, 4 or 6 rows tall. Her speech goes into an Option B compartment inside the HUD frame.

**Architecture:** The Rust binary gets a long-lived `purrgotchi band` subcommand. It samples the same deterministic life/scene/fx model as the statusline at `now_ms` and paces NDJSON frames itself. Each frame is base64 Raster cells. The in-repo mod `mod/` spawns the stream from `session.start` and blits the latest line into one `Raster`. It also writes a per-session heartbeat file that makes the statusline drop its cat and draw the speech compartment.

**Tech Stack:** Rust (std + serde/serde_json, no new crates). Claude Code 2.1.302 mods API (TypeScript, `claude plugin test`, `tsc`, `claude plugin validate`). Python 3 pty harness for the live check.

## Gaps the design left open, settled here

1. **Tempo.** Decision 1 asks for one model sampled faster, whose whole-second samples reproduce today's output. But today's speeds (walk 2 px/s, blocks that move the anchor ≤ 11 px per 30 s) can't cover a 130-px band at 30 fps. So the model takes a `Tempo` struct of speeds and periods. Both the statusline and the band use the same code. `Tempo::STATUSLINE` holds today's constants, and its whole-second samples are pinned byte-identical. `Tempo::BAND` is faster and spans the full width. The two never show at once, because the statusline hides its cat while the band is live. Scene identity, elapsed time and finale come from shared state, so captions stay in sync.
2. **The compartment shows only while the band is alive.** This follows from the goldens invariant. Without a band, v4.0.0 output is unchanged, loose speech line included.
3. **Compartment geometry.** The compartment shares the HUD's right border column. `cw = min(50, COLUMNS − 98)`, inner `cw − 2` (30 at 130 cols, as the design says), text width `cw − 4` (1-space pad each side), line width `95 + cw ≤ COLUMNS − 3`. No quotes, and the text block is centred vertically in the 5 inner rows. Both come from mockup B (`.superpowers/brainstorm/1059835-1792262508/content/speech-box.html` in the main repo). The pad follows the design's 1 space, not the mockup's 2.
4. **Resize and mood changes respawn the stream.** `$.process.spawn` closes stdin from the start (`ProcessSpawnRequest.input` is one-shot), so there is no control channel. A new `bodyColumns`/rows, or a context-% mood bucket change (≤ 40 / ≤ 80 / > 80, read from `(await $.session.usage()).context.percent`), respawns with new argv, debounced 300 ms. Otherwise the band would show a calm cat while the statusline says "panic".
5. **Heartbeat content is epoch ms, not mtime.** `$.clock.now()` is epoch ms (d.ts: "Resolves milliseconds since the epoch"), so goldens can pin freshness under `PURR_NOW`. The stream's hello line gives the mod the state dir, so the mod never duplicates `PURR_STATE_DIR`/HOME logic. `$.fs` has no remove, so the stream prunes `band-*.alive` files whose mtime is older than 24 h when it starts.
6. **The band never mutates state.** It doesn't call `advance`, doesn't consume quips (it passes `|| None` as the quip source), never calls `load_or_hatch`, and re-reads `state.json` at most once per second.
7. **Defaults.** `PURR_BAND_ROWS` defaults to `4`. An invalid value means 4. `PURR_BAND_FPS` defaults to `30`, clamped to 15–60. The band needs at least 24 `bodyColumns`, or it draws nothing.
8. **No permanent give-up.** After 3 unexpected exits within 60 s the mod retries every 60 s instead of stopping (anti-goal: "never comes back").
9. **Base64 and CJK width are hand-rolled.** There are no new crates. `px::band::base64` is tested against RFC 4648 vectors. `span::cell_width` is a compact East Asian Wide/emoji range table, used only by the compartment.

## Review Focus

1. **Stale band, cat lost.** The mod crashes, the band is collapsed, or a survey takes it. The cat must come back in the statusline within 3 s, because the heartbeat stops when blits stop being accepted. Owner: Task 3.2 (`heartbeat stops when blits are denied`).
2. **`/clear` swaps the session id with no `session.start`.** The heartbeat must follow the new id, not keep the old one fresh. Owner: Task 3.2 (`heartbeat follows a new session id after clear`).
3. **Terminal narrower than 98 + 20, or COLUMNS unset.** The compartment must never wrap the statusline. It falls back to the loose line. Owner: Task 3.4 golden cases `band_cols_117_fallback` and `band_no_columns_fallback`.
4. **Resize storm** (dragging the window). It should cause one respawn after things settle, not one per event, and no blits of the wrong size kept as "ok". Owner: Task 1.4 (`resize storm respawns once`).
5. **Old or missing binary** (`PURR_BIN` points at v4.0.0, which has no `band` verb and exits 2). The band draws nothing and the statusline keeps the cat. There must be no spawn loop faster than the backoff. Owner: Task 1.4 (`old binary backs off and never blits`).

- Produces:
  - **CLI:** `purrgotchi band --cols N --rows R [--fps F] [--context-pct P] [--now-ms T --frames K]`.
    - `cols` must be in 1..=512 and `rows` must be in {6} (Task 1.6 widens this to {3,4,6}). Anything else exits 2 with `band: <msg>` and the usage line on stderr.

  - **NDJSON, one object per line:**
    - First line: `{"v":1,"hello":true,"cols":C,"rows":R,"fps":F,"state_dir":"<abs>"}`
    - Frame: `{"v":1,"f":<i>,"t":<now_ms>,"c":"<base64 cells>"}`
    - Read failure: `{"v":1,"ok":false,"error":"no_kitten"|"state_unavailable"|"state_corrupt","message":"…"}`, at most once a second. The stream keeps running and recovers when state appears.
  - **Loop:**
    - Pace with an `Instant` deadline as `producer.py` does: `next += period`, and if late, `next = now`.
    - Real `now_ms` = epoch ms. Under `PURR_NOW`, use `PURR_NOW*1000 + elapsed`.
    - Re-read state when `t - last_load >= 1000`. Recompute `kitten_view` when `t/1000` changes. Its `ViewInput` gets `now: t/1000`, `frame: (t/1000 % 2) as u8`, `ctx_pct: context-pct`, `strip_width: Some(cols)` (unclamped: `clamp_strip` caps at 120 and would hide scenes on wide bands), and `forced_scene`/`playground_enabled` as the statusline reads them.
    - Skip a frame whose cells equal the last emitted ones unless ≥ 1000 ms have passed since the last line (keepalive). Test mode uses the same rule on virtual time.
    - Write with `writeln!` and flush on a locked stdout. Any write error → return 0 (never `println!`: `panic = "abort"`).
    - Never read stdin.
    - At start, delete `state_dir/band-*.alive` with mtime older than 24 h.
  - Phase 1 samples the model at `now = t/1000` with `cat_canvas` at the band width `cols` (12 px only; Task 1.5 adds heights).

  - `export function pickRows(requested: 3 | 4 | 6, maxRows: number): 3 | 4 | 6 | 0`: `requested` if it fits, else the largest of 6, 4, 3 that does, else 0.
  - `export function bandArgv(bin: string, cols: number, rows: 3 | 4 | 6, fps: number, ctxPct: number): string[]` = `[bin,'band','--cols',`${cols}`,'--rows',`${rows}`,'--fps',`${fps}`,'--context-pct',`${Math.round(ctxPct)}`]`
  - `export function blankCells(cols: number, rows: number): string`: base64 of default-colour spaces, via native `Uint8Array.prototype.toBase64`.
  - Module state `B: { opts: BandOptions | null; bin: string | null; requestId: string; cols: number; rows: 3 | 4 | 6 | 0; helloCols: number; helloRows: number; cells: string | null; lastOkAt: number; lastLineAt: number; stateDir: string | null; ctxPct: number }`
  - `export function onBandLine($: BlitHost, line: string): void`:
    - A hello line sets `helloCols`, `helloRows` and `stateDir`.
    - A frame line whose hello size equals the mounted size stores `cells` and blits `{ requestId, key: 'purr-band', cells }`. An ok result sets `B.lastOkAt = await $.clock.now()`. A deny only counts.
    - An error line blits `blankCells` once and clears `cells`.
- Render hook (`ui.render` `{ component: 'AbovePrompt' }`). Its only `$` call is `$.ui.resolve(e)`. It never spawns, starts a timer or blits; it only records `B.requestId`, `B.cols` and `B.rows`.
  - Pass `next(e)` when any of these hold: `e.surface !== 'terminal'`, `e.props.hasSurvey`, options not read yet, `bin === null`, `pickRows(...) === 0`, `bodyColumns < 24`. In those cases set `B.rows = 0`.
  - Otherwise set `B.cols = min(512, bodyColumns)` and `B.rows = pickRows(opts.rows, maxRows)`.
  - Return `Raster({ key: 'purr-band', columns: cols, rows, cells: sizeMatches ? B.cells : blankCells(cols, rows) })`.
- `export function reconcile($: StreamHost): void`. It runs from `$.clock.every(100, …)`, started in `session.start`, so every spawn and timer lives on session.start's `$`, as old `serve.ts` and the spike's `maybeSpawn` do.
  - When `B.rows > 0` and no stream exists, it calls `startStream`.
  - When `bandArgv(B…)` differs from `s.wanted`, it calls `streamWants`.
  - When `B.rows === 0` while a child runs, it calls `streamWants` with the same argv. It doesn't stop the child: a survey is brief.
- `session.start`:
  - `await next(e)` first.
  - Read the options and locate the binary.
  - Start the `reconcile` clock.
  - Call `$.ui.invalidate('ui.render')`, because the band rendered about 40 ms before start finished.
- `session.end`: do nothing. `/clear` keeps the child.
