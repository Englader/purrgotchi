# Mods API findings: Claude Code 2.1.302

**Date:** 2026-10-17
**Purpose:** get ground truth on the mods API before planning Phases 1–4 of `docs/superpowers/specs/2026-10-17-v4.0.0-claude-code-mod-design.md`.
**Engine:** `claude --version` → `2.1.302 (Claude Code)`; `$.session.version()` → `{"version":"2.1.302","base":"2.1.302","builtAt":"2026-10-16T15:52:41Z"}`.
**Method:** I built throwaway mods in `/tmp/claude-1000/purr-mod-probe{,2,3}`, got 2.1.302 to write its generated types, read the d.ts, and ran `claude plugin validate`, `claude plugin test` and `tsc`. I also ran three real sessions: two interactive sessions inside a pty, and one cheap `claude -p --model haiku` run to capture event payloads.

Legend: **OK** means it matches the spec. **DIFF** means the spec is wrong or needs changing. **VERIFIED** means I saw it at runtime, not just in the d.ts.

## 1. Generated types (the authority)

- **Validation never lays types.** The engine writes `.claude-plugin/types/` only when an **interactive** session loads the mod from a hot-reloaded folder (`--plugin-dir`, `CLAUDE_CODE_PLUGIN_DIRS`, or the session's mods folder). `claude -p` and installed plugins never get them.
- **Laid files** (debug log line: `type root of <plugin> at …/.claude-plugin/types: … wrote …`):
  - `.claude-plugin/types/claude-code/index.d.ts`: the API, 651,888 bytes, 16,700 lines.
  - `.claude-plugin/types/claude-code-tools/index.d.ts`: built-in tool inputs (186 KB), so `e.tool === 'Bash'` narrows.
  - `.claude-plugin/types/claude-code-mcp/index.d.ts`: the MCP tools connected at the last reload.
  - `.claude-plugin/types/tsconfig.json` and `.claude-plugin/types/.gitignore` (contents `*`). The engine ignores the types folder itself.
  - `<mod>/tsconfig.json` = `{ "extends": "./.claude-plugin/types/tsconfig.json" }`. This one is meant to be committed.
- **The d.ts is not copied into the repo.** At 651 KB it is over the ~300 KB cap. If you want it in-repo, gzip it (about 175 KB).
- **Regeneration recipe.** No API call is needed; the session just idles and gets killed:
  ```bash
  timeout 25 script -qfc "claude --plugin-dir ./mod --debug-file /tmp/purr-debug.log" /tmp/purr-tty.log </dev/null >/dev/null
  ls mod/.claude-plugin/types/claude-code/index.d.ts
  ```
  Without a pty you can use the copy the `plugin-authoring` skill writes when it loads, but that copy belongs to the *running* session's build, which may be older (this machine's live session was 2.1.296).
- **Churn is real (spec §7 Q1).** The 2.1.296 → 2.1.302 d.ts diff is about +12.9k / −17.6k lines. Regenerate on every bump; never hand-edit.
- **Type-check:** `tsc -p mod` with TypeScript 5.9 passes against the laid tsconfig. **`claude plugin validate` does NOT type-check.** It accepted `$.process.run({ argv })`, which is the wrong shape. Make `tsc -p mod` a required gate in Phase 1.

Quick way to find a declaration: `grep -n "export type ProcessRunInit" mod/.claude-plugin/types/claude-code/index.d.ts`.

### Testing (`claude plugin test`)

- It runs every `*.test.ts` / `*.test.tsx` under the folder (hooks/ is fine), each file in its own child process. It imports `test, expect, mock, describe, tier` from `'claude-code/testing'`. `test(name, { options?, plugins?, timeoutMs? }?, ($, on) => …)`, with a default timeout of 5 s.
- **Nothing sits beneath the plugin.** The test's `on` hooks *are* the engine. Anything the plugin reaches that isn't answered fails with `no implementation for <event>`. The exceptions are `$.state` and `session.append`, which the kit provides.
  - **Op mocks return `{ value }` or `{ deny }`**, not a bare value: `on('process.run', ($, e) => ({ value: { exitCode: 0, stdout, stderr: '', isStdoutTruncated: false, isStderrTruncated: false } }))`. In the mock, `e` is `{ argv, init? }`.
  - Engine events return their result directly: `on('session.start', ($, e) => ({ cwd: e.cwd }))` and `on('tool.call', () => ({ result: 'x' }))`.
  - `$.session.start(...)` needs `session.start` and `command.register` answered.
  - `$.command.run` in a test takes the **full** `CommandRunInput` (`args`, `origin`, `presentation`).
  - A `$.process.run` that fails is mocked as `({ deny: '…' })`, which makes the plugin's call reject.
  - Classic events are raised as `$.classic.UserPromptSubmit({ prompt, session_id?, transcript_path? })`, with `on('classic.UserPromptSubmit', () => ({}))` answered beneath.
  - **The test's `$` has no `state` noun.** Assert state through a render, or spy on `ui.toast` etc.
- UI: `const pane = await $.ui.mount({ plugin, surface, component: 'Pane', requestId, props })`, then `pane.find({ text })`, `findAll`, `press({ key })`, `input`, `redraw(props)`. Looping over `['terminal','desktop','mobile'] as const` works.
- The mocked clock is `mock.clock(on)`, with `.advance(ms)` and `.settle()`.

`hooks/register.tsx`
```tsx
import { atom, read, update } from 'claude-code'
import type { Register } from 'claude-code'

import type { Feed } from '../types'

const calls = atom({ plugin: 'purrprobe', key: 'calls' } as const, 0)
const lastFeed = atom({ plugin: 'purrprobe', key: 'lastFeed' } as const, null as Feed | null)

export const register: Register = (on, options) => {
  const bin = typeof options.binaryPath === 'string' && options.binaryPath !== '' ? options.binaryPath : 'purrgotchi'

  on('session.start', async ($, e, next) => {
    await $.command.register({ name: 'pet', description: 'Pet the kitten' })
    return next(e)
  })

  on('command.run', { command: 'pet' }, async $ => {
    try {
      const r = await $.process.run([bin, 'pet', '--json'], { timeoutMs: 2000 })
      if (r.exitCode !== 0) return { text: 'The kitten is asleep.' }
      const out = JSON.parse(r.stdout) as { message: string }
      return { text: out.message }
    } catch {
      return { text: 'Purrgotchi binary not found.' }
    }
  })

  on('tool.call', async ($, e, next) => {
    const ran = await next(e)
    try {
      await update($, calls, n => n + 1)
      const r = await $.process.run([bin, 'feed', '--json'], { timeoutMs: 2000 })
      if (r.exitCode === 0) {
        const feed = JSON.parse(r.stdout) as Feed
        await update($, lastFeed, () => feed)
        if (feed.celebration !== null) $.ui.toast(`Celebration: ${feed.celebration}`)
      }
    } catch {
      // observer: a Purrgotchi failure never affects the tool call
    }
    return ran
  }).catch(($, e, next) => next(e))

  on('classic.UserPromptSubmit', async ($, e, next) => {
    try {
      const stdin = JSON.stringify({ session_id: e.session_id, transcript_path: e.transcript_path })
      await $.process.run([bin, 'turn', '--json'], { stdin, timeoutMs: 2000 })
    } catch {
      // observer
    }
    return next(e)
  }).catch(($, e, next) => next(e))

  on('ui.render', { component: 'Pane', requestId: 'kitten' }, async ($, e) => {
    const { Box, Text } = $.ui.resolve(e)
    const n = await read($, calls)
    return (
      <Box flexDirection="column" borderStyle="round" borderColor="#ea00d9">
        <Text color="#0abdc6" mono>{`=^.^= calls ${n}`}</Text>
        <Text dimColor>{`width ${e.props.bodyColumns} ${e.props.placement}`}</Text>
      </Box>
    )
  })
}
```

## 5. Spec §7 open questions

- **Q1 API churn:** confirmed. The d.ts changed by about 30k lines between 2.1.296 and 2.1.302. Pin `>=2.1.302` in the README and regenerate the types per bump.
- **Q5 `transcript_path`:** `prompt.submit` does **not** carry it (`text, wait, origin`). **`classic.UserPromptSubmit` does**, along with `session_id`, `cwd`, `prompt` and the rest of the classic stdin, verified in a real run. It fires after `prompt.submit` and without any settings hook. Every `classic.*` event carries the base fields, including `classic.PostToolUse`.
- **Q6 Desktop surface:** no desktop client was available here. From the d.ts: desktop gets `Svg` (no `Raster` or `Image`), `Text` takes `mono` (desktop draws its monospaced face; the terminal ignores it), and `color` accepts hex. `$.ui.notify` returns `no-surface` in the desktop app. `$.process.run` is documented "CLI only", but the desktop Code tab runs the CLI underneath, so it should work there. **Unverified; test it in Phase 2.**
- **Q7 Command namespacing:** **`/pet`, not `/purrgotchi:pet`.** Built-in names are refused at registration: **`/stats` (an alias of `/usage`) and `/rename`** are taken.

## 6. Spec changes needed

1. **§4.1 / §3 `$.process.run`:** write it argv-first: `$.process.run([bin, 'turn', '--json'], { stdin, timeoutMs })`. Handle both a rejection (timeout, missing binary) and a non-zero `exitCode`.
2. **§4.1 latency:** drop "`$.process.run` time counts against the hook". The real cost is that awaiting the feed delays the tool result. Options: (a) `const r = await next(e); void feed($); return r` (fire-and-forget after `next`; check in Phase 1 that a `$` call outliving its hook still runs), or (b) bump an atom per call and flush `feed --count N` from a `$.clock.every(2000)` started in `session.start`, which is a long-lived context. Prefer (b) if (a) misbehaves.
3. **§4.1 port option:** consider `classic.PostToolUse` → `feed` and `classic.UserPromptSubmit` → `turn`, passing `JSON.stringify(e)` as stdin. That keeps the binary's existing stdin contract byte-for-byte (`session_id`, `transcript_path`, …). Use `tool.call` only if you need the result shape.
4. **§4.1 double-feed check:** use `$.settings.read({ source: 'user' })` instead of `$.fs` on `~/.claude/settings.json`.
5. **§4.2 commands:** the names are bare `/pet` etc. **Rename `/stats` and `/rename`.** For example, make `/kitten` a hub (`/kitten stats`, `/kitten rename <name>`, `/kitten layout …`), or use `/purr-stats` / `/purr-rename`. Update §2 goal 2 ("`/purr:pet`-style") and §7 Q7.
6. **§4.3 auto-open:** `session.start` has no `viewport`. Either just call `$.ui.open` in `session.start` and read `isPlaced` (unasked opens wait below 144 columns, 110 once the person has opened it), or record `e.viewport?.isFullscreen` from the first `ui.render` (e.g. the band or `PromptHint`) and open from a `$.clock.after(0, …)`. Fix "docked … from 110 columns" in §4.10: that is for *asked* opens; unasked opens need 144.
7. **§4.3 `serve`:** `$.process.spawn` closes stdin right away (or after `input`). `serve` must **not** exit on stdin EOF. The engine kills it when the loop ends or the module unloads. Its output arrives in raw chunks, so buffer and split on `\n`. Restart it on hot reload (`session.start` fires again).
8. **§4.4 notify:** note that `$.ui.notify` only reaches iTerm2/kitty/Ghostty/bell terminals and returns `no-surface` on desktop. Toasts are the real channel.
9. **§4.5 / §4.8 pane data:** `session.measure` gives `context.{tokens,window,percent}`, `rateLimits[{kind,percentUsed,resetsAt}]` and `cost.usd`, but **not** lines added/removed, and not the model or duration. Use `$.session.model()` and `$.session.usage().startedAt`. Lines added/removed has no mod source; drop it from the mockup or keep it classic-only. `cost` can be absent.
10. **§4.7 `userConfig`:** add the required `title` and `description` to every field. Make `binaryPath` `type: "file"`. Config keys for `$.config.set` are `purrgotchi.<field>`, and a change reloads the module.
11. **§4.9 theme:** the stored setting is `custom:purrgotchi:netrunner`, not `custom:netrunner`. `themes/` is auto-discovered. Restrict overrides to real palette keys (unknown ones are silently dropped). Colours are hex or `rgb()`.
12. **§4.9 restyle rule:** `ToolUse` has no `isExpanded`. Gate compaction on `UserMessage.isExpanded` / `ToolGroup.isExpanded` only, and keep `ToolUse` restyles to a one-line chip that doesn't hide output.
13. **§5 Phase 1 "done when":** add `tsc -p mod` clean (validate doesn't type-check) and the §1 type-laying recipe. Phase 2's "tested on terminal and desktop" is supported by `$.ui.mount({ surface })` loops.
14. **§6 testing:** document the `{ value }` / `{ deny }` op-mock shape, answering `session.start` and `command.register` beneath, the full `CommandRunInput` for `$.command.run`, `$.classic.<Event>(…)`, and the fact that the test's `$` has no `state`. §3 above is the template.
15. **§8 checklist:** add the pty type-laying command and `npx tsc -p mod`. `claude plugin init` is not for mods.
16. **§3.2 / §8 caution:** while developing, `PATH` resolution will find a real `purrgotchi` and touch `~/.claude/purrgotchi`. Point `binaryPath` at a build that uses `PURR_STATE_DIR` (worth adding, as §8 already suggests), or test only through `claude plugin test` mocks.
