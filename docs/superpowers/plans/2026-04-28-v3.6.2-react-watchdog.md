# v3.6.2 React Watchdog Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bound the lifetime of detached `purrgotchi react` workers with a 30s wall-clock watchdog, and turn three `dead_code` warnings into useful debug-log output.

**Architecture:** Add an `impl Display for LlmProviderError` and switch the two `err={e:?}` debug-log call sites to `err={e}` (resolves dead-code warnings + improves observability). Add a fire-and-forget watchdog thread at the top of `react::run` that logs + force-exits the process after 30 seconds of wall-clock time, killing any zombie HTTP socket and freeing the binary handle on Windows.

**Tech Stack:** Rust 2021, `std::thread`, existing `crate::debug::log`. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-04-28-v3.6.2-react-watchdog-design.md`

**Bin-only crate reminder:** This is a bin-only Rust project — there is no `lib.rs`. Run tests as `cargo test` (NOT `cargo test --lib`) from the `rust/` directory.

```rust
    #[test]
    fn watchdog_action_fires_after_deadline() {
        use std::sync::atomic::{AtomicBool, Ordering};
        use std::sync::Arc;
        use std::time::Duration;

        let fired = Arc::new(AtomicBool::new(false));
        let f = fired.clone();
        spawn_watchdog_with_action(Duration::from_millis(50), move || {
            f.store(true, Ordering::SeqCst);
        });
        // Sleep well past the deadline to avoid timing flakes on slow CI.
        std::thread::sleep(Duration::from_millis(250));
        assert!(fired.load(Ordering::SeqCst), "watchdog action did not fire after deadline");
    }
```

```rust
/// Generic watchdog: sleep `deadline`, then run `action` on a background thread.
/// Detached — the caller does not join. Extracted from `spawn_watchdog` so the
/// timing behaviour can be unit-tested without invoking `process::exit`.
fn spawn_watchdog_with_action<F>(deadline: Duration, action: F)
where
    F: FnOnce() + Send + 'static,
{
    std::thread::spawn(move || {
        std::thread::sleep(deadline);
        action();
    });
}

/// Wall-clock guard for the detached `purrgotchi react` worker. After the
/// deadline elapses, log a breadcrumb and force-exit the process so a stalled
/// HTTP call cannot keep `purrgotchi.exe` open and block future cargo builds
/// (Windows zombie-binary problem). Exit code 0 is consistent with the rest of
/// `react::run` — every failure here is non-fatal and silent.
fn spawn_watchdog(deadline: Duration) {
    spawn_watchdog_with_action(deadline, || {
        crate::debug::log("[llm] react fail reason=watchdog_timeout");
        std::process::exit(0);
    });
}
```

```markdown
## v3.6.2 — 2026-04-28

### Fixed

- **React worker zombie on Windows.** The detached `purrgotchi react` worker
  could hang indefinitely when the underlying HTTP call stalled (TLS handshake,
  slow proxy, provider rate-limiting), because `ureq`'s per-operation timeouts
  do not always fire end-to-end on Windows. The hung process kept an open
  handle on `purrgotchi.exe`, blocking subsequent `cargo build` runs with
  "Access is denied". A 30-second wall-clock watchdog is now installed at the
  top of `react::run`; on expiry it logs `[llm] react fail reason=watchdog_timeout`
  (visible only when `PURR_DEBUG=1`) and force-exits the process with code 0.
  Exit code matches the rest of `react`'s silent-fallback convention.

### Changed

- **Error logging legibility.** `LlmProviderError` now implements `Display`,
  and the `err={e:?}` debug-log lines in `hatch.rs` and `react.rs` switch to
  `err={e}`. HTTP status codes (`HTTP 429: rate limit exceeded`) and error
  messages now surface as one-line summaries in `debug.log` instead of being
  buried in derived-`Debug` formatting. This also resolves the three
  `dead_code` warnings carried since v3.6.0.
```
