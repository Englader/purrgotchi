# v4.0.0 Phase 3: Live Pane, Band, Status Entry and Layouts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The kitten lives in a live, animated pane, or in a band above the prompt when `layout: "bottom"`. A clock drives it instead of a 1 Hz statusline respawn. Session, context and rate-limit data come from the engine, and a one-line status entry covers the case where no pane is open.

**Architecture:**
- **Ticker.** A per-runtime `FrameTicker` (started in `session.start`) calls `frame --json` every second. It passes `--width`, `--context-pct`, and `--advance` when no classic statusline is installed, and writes the result into a `frame` atom. The pane, band and status entry are pure readers of the `frame` and `measure` atoms.
- **Measure.** `session.measure` (pushed by the engine) feeds the `measure` atom.
- **Binary.** It gains one additive `hud` object in `frame --json`, so the pane shows every HUD datum without duplicating game rules in TypeScript.

**Tech Stack:** Rust 2024 (one additive JSON field), Claude Code 2.1.302 mods API (`Pane`, `AbovePrompt`, `$.ui.open`, `$.ui.status`, `$.clock.every`, `$.config.set`), `claude plugin test` with `mock.clock` and `$.ui.mount`.

**Spec:** `docs/superpowers/specs/2026-10-17-v4.0.0-claude-code-mod-design.md` §4.3, §4.5, §4.8 (pane layout; pixel sprites are Phase 3b), §4.10, §5 row 3. **Overrides:** `docs/superpowers/plans/2026-10-17-v4.0.0-mods-api-findings.md`. **Binary contract:** `docs/superpowers/plans/2026-10-17-v4.0.0-phase0-json-surface.md` Task 7 (`frame`). **Builds on:** Phase 1 (`…-phase1-mod-skeleton-hooks.md`: Global Constraints and File Map apply verbatim) and Phase 2 (`…-phase2-commands-toasts.md`: `runAction`, `renderLines`, `COMMANDS`, `rt.kitten`).

## Global Constraints

All of Phase 1's Global Constraints apply, plus:

- **The palette is `colors.rs`'s, verbatim** (spec §4.8): magenta `#ea00d9` (frame, accents), cyan `#0abdc6` (primary data), yellow `#f3f31b` (money, limits), purple `#711c91` / `#b45cff` (section rules), mint `#57eca6` (good), red `#ff5468` (danger), labels `#6d6488` (dim). Chrome colours live in `hud.ts` `PALETTE`. Game colours (name/rarity, sprite, speech, scene) always come from the binary's spans or `hud.name_fg`, never from a TypeScript rarity table.
- **Bars are 10 segments of `▰` / `▱`**, with `filled = clamp(round(pct / 10), 0, 10)`.
- **Render hooks are pure readers.** They `read` atoms; the one allowed side effect is recording layout hints in `rt.view` (a plain object: `paneColumns`, `bandColumns`), which the ticker reads for `--width`. They never call `$.process.run`, `update` or `$.ui.status`.
- **Unasked `$.ui.open`** (from `session.start` or a timer) is placed only from 144 columns, or 110 if the person opened this id before. Otherwise it **waits undrawn**, and the engine places it when the terminal permits. **Asked opens** (`/purr`) place at any width: docked in fullscreen from 110 columns, otherwise inline. The mod never computes viewport thresholds itself.
- **`session.measure` has no lines added/removed, no model and no duration** (findings). The model comes from `$.session.model()`, the duration from `$.session.usage().startedAt` (a number, epoch ms), and the cwd from `$.session.cwd()`. **Lines added/removed are dropped from the pane** (classic statusline only). `cost` can be absent, in which case the row is omitted.
- **`/clear` fires `session.end` with no `session.start` after it.** The ticker is never stopped on `session.end`. It dies with the module (reload) and restarts in the next `session.start`.

**Deviations from spec (intentional):**
- §4.3 "`session.start` only where `e.viewport.isFullscreen`": `session.start` has no viewport. The mod just calls `$.ui.open` unasked and lets the engine's 144/110-column rule decide (findings §6.6).
- §4.5 band behind `userConfig.band`: this is superseded by `layout: "bottom"` (§4.10). There is no separate `band` option.
- §4.8 pane `lines +218 -41`: dropped (no mod data source). `cost $x turn`: only the session cost (`measure.cost.usd`) is available, shown as `cost $0.12 session`. Phase 4 adds the lifetime `total` from `cost --json`.
- §4.3 `frame --tick`: not passed. The binary defaults `tick` to `now`, which already alternates sprite parity every second.

## Review Focus

1. **A slow or hung `frame`.** Ticks must not pile up as N concurrent `frame` processes (it is single-flight), the pane keeps the last good frame, and nothing toasts. Pinned in Task 3.2 (`single-flight under a hung frame`).
2. **Narrow docks and inline panes.** `bodyColumns` of 30, 44, 56 and 80. Expected: at ≥ 56, sprite and stats sit side by side; from 40 to 55 they stack; below 40 only the kitten section and the buttons show (mobile). No row is ever wider than `bodyColumns`, and the scene strip width passed to the binary is `bodyColumns - 4` (or `0`, meaning no scene, when that is below 24). Pinned in Task 3.3.
3. **No kitten yet, or binary missing, while the pane is open.** The pane shows a placeholder (`No kitten yet — it hatches on your first tool call.` / the not-found text), not an empty box or a thrown render. Pinned in Task 3.3.
4. **Classic statusline also installed.** The pane tick must run `frame` **without** `--advance` (the statusline advances), and with `--advance` when it is absent. Pinned in Task 3.2.
5. **Rate-limit windows missing or unknown** (`spend_limit`, an empty array, no `resetsAt`). The LIMITS section shows only the windows present, with no `NaN`, no `undefined`, and no negative "resets" values. Pinned in Task 3.2 (`hud.ts` formatters) and Task 3.3.

**Interfaces:**
- Produces from `hud.ts` (all pure):

  - `bar(pct: number): string`: exactly 10 chars. NaN or negative is treated as 0, and > 100 as 100.
  - `ago(secs: number): string`: `<60` → `12s ago`, `<3600` → `4m ago`, `<86400` → `3h ago`, else `2d ago`; negative → `just now`.
  - `duration(ms: number): string`: `45m 0s`, `2h 05m`, `3d 4h`.
  - `resetsIn(resetsAt: string | undefined, nowMs: number): string | null`. It returns `null` when `resetsAt` is absent or unparsable, `<1m` when ≤ 0 or under a minute, and otherwise `2h 00m` / `4d 15h` / `37m`.
  - `kTokens(n: number | null): string | null`: `87k`, `1.2M`.
  - `shortCwd(p: string | null): string | null`: the last two path segments, `/` or `\` separated.
  - `statusText(f: FrameJson | null): string | undefined`: `=^.^= {name.toLowerCase()} lv{level} · {coins}¢ · {mood}` (spec §4.8), or `undefined` for null.
- Produces `MeasureView = { contextPct: number | null; contextTokens: number | null; contextWindow: number | null; rateLimits: { kind: string; percentUsed: number; resetsAt?: string }[]; costUsd: number | null; model: string | null; cwd: string | null; startedAt: number | null }`, and `measureAtom = atom({ plugin: PLUGIN, key: 'measure' } as const, EMPTY_MEASURE)`.
- Produces `seedMeasure($): Promise<void>`. It calls `$.session.usage()`, `$.session.model()` and `$.session.cwd()`, each in its own try/catch, and writes the atom.
- Produces `registerMeasure(on, rt)`, which registers `on('session.measure', async ($, e, next) => { const r = await next(e); try { …update measureAtom from e.context / e.rateLimits / e.cost…; if (e.changed.includes('context')) rt.ticker?.poke($) } catch {} return r })`. Read the exact `session.measure` event shape and its result type from the d.ts. If the result is void, return `next(e)` as-is.
- Produces `frameAtom = atom({ plugin: PLUGIN, key: 'frame' } as const, null as FrameJson | null)`.
- Produces `tickIntervalMs(layout: PurrOptions['layout']): number | null`: `dock`/`bottom` → `1000`, `classic` → `5000`, `off` → `null`.
- Produces `frameArgv(o: { width: number; ctxPct: number | null; advance: boolean }): string[]`, which is `['frame','--json','--width', String(max(0, floor(width))),'--context-pct', (ctxPct ?? 0).toFixed(1)]` plus `'--advance'` when `advance`. Width `0` makes the binary draw no scene (`clamp_strip` below 24 returns `None`), and it never falls back to the inherited `COLUMNS`.
- Produces `stripWidth(rt): number`. It is `rt.view.paneColumns - 4` when the layout is `dock` and `paneColumns` is known, `rt.view.bandColumns - 40` for `bottom`, else `0`. The result is `0` when below 24 and capped at 120.
- Produces `class FrameTicker { constructor(rt: Runtime); start($): void; poke($): void }`:
  - `start` is idempotent. It sets up `$.clock.every(tickIntervalMs(layout), () => this.tick($))` and runs one immediate tick.
  - `tick` is **single-flight**: it returns at once if a tick is in flight. It calls `runJson<FrameJson>($, rt.bin, frameArgv({ width: stripWidth(rt), ctxPct: rt.ctxPct, advance: !rt.scan.classicStatusline }), { timeoutMs: TIMEOUT.frame })`. It does **not** go through `rt.serial`: `frame` is read-mostly, and `--advance` takes the state lock itself.
    - `ok` → `update(frameAtom)`, `rt.kitten` ← name/level/stage/rarity/breed, and `setStatus`.
    - `isError` with `no_kitten` → `update(frameAtom, () => null)` and the status is cleared.
    - `failed` → keep the last frame, increment `rt.frameFailures`, and `$.ui.log` at the 5th consecutive failure only. There is never a toast.
  - `poke` runs an immediate tick (still single-flight).
- Produces `setStatus($, rt, text: string | undefined)`, which calls `$.ui.status(text)` only when `text !== rt.lastStatus`.
- `Runtime` additions: `ticker?: FrameTicker`, `view: { paneColumns: number | null; bandColumns: number | null }`, `ctxPct: number | null`, `lastStatus?: string`, `frameFailures: number`. `registerMeasure` sets `ctxPct`.
- `onSessionStart`: when `ready` and `tickIntervalMs(layout) !== null`, it runs `await seedMeasure($)`, writes the handshake `frame` into `frameAtom` and the status, then `(rt.ticker ??= new FrameTicker(rt)).start($)`.
- `commands.ts`: after any successful `runAction`, `purr-rename` or `purr-hatch`, call `rt.ticker?.poke($)`. `play` starts a scene, so the pane shows it within one tick.
