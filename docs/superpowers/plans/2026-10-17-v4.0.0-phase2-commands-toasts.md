# v4.0.0 Phase 2: Slash Commands + Celebration Toasts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Real `/purr-*` slash commands replace the shell-only `purr` wrapper. Card and stats render as coloured spans inline in the transcript. Every celebration the binary reports (level-up, evolution, milestones, streaks, drops, greeting, first hatch) becomes a toast, with a native notification for the rare ones.

**Architecture:** Commands are registered in `session.start` and answered in `command.run` by running the binary's `--json` verbs through `binary.ts`. A command's `text` is short and in character, because the model reads it. The full card/stats spans go into an `outputs` atom keyed by `(command, text)`, which a `CommandOutput` render hook reads and draws. Celebrations come from the `FeedJson` / `TurnJson` that Phase 1's queue already receives.

**Tech Stack:** Claude Code 2.1.302 mods API (TS/TSX), `claude plugin test` with mocked `process.run`, TypeScript 5.9 for type-checking only.

**Spec:** `docs/superpowers/specs/2026-10-17-v4.0.0-claude-code-mod-design.md` §4.2, §4.4, §5 row 2. **Overrides:** `docs/superpowers/plans/2026-10-17-v4.0.0-mods-api-findings.md`. **Binary contract:** `docs/superpowers/plans/2026-10-17-v4.0.0-phase0-json-surface.md` (Tasks 4–6). **Builds on:** `docs/superpowers/plans/2026-10-17-v4.0.0-phase1-mod-skeleton-hooks.md`: read its Global Constraints and File Map first; they apply here verbatim.

## Global Constraints

All of Phase 1's Global Constraints apply, plus:

- **Command names** (decided in Phase 1, verified on 2.1.302): this phase registers `purr-pet`, `purr-play`, `purr-treat`, `purr-rename`, `purr-card`, `purr-stats`, and `purr-hatch` (only when `devCommands`). `purr` and `purr-layout` arrive in Phase 3. Registration names are bare: the engine adds the slash and no namespace.
- **Each `$.command.register` call sits in its own try/catch.** A refusal (for example, a future built-in taking the name) logs `$.ui.log('command /<name> refused: …', { to: 'debug' })` and skips that one command. It never fails `session.start`.
- **Commands are registered whenever the game is enabled (`layout !== 'off'`), even if the binary is missing.** The handler then answers "Purrgotchi binary not found — set Binary path in /config or run `cargo install --path rust`" instead of leaving the command unknown.
- **The model reads `text`.** It is one or two lines, in character, and never the full card. Full card/stats content is drawn by the render hook only.
- **Render hooks never write atoms and never run processes.** `command.run` does the I/O and writes `outputs`. `ui.render` only `read`s.
- **Toasts:** at most one per binary result, and `$.ui.toast` replaces the plugin's previous toast, so bursts self-limit. `$.ui.notify` is fire-and-forget (`void`). It returns `no-surface` on desktop, SDK and `-p` (findings), and the result is ignored.

**Deviations from spec (intentional):**
- §4.2 "toast if bond tier changed": `bond.rs` has no tier concept, and pet's message already reports the bond change. No bond toast.
- §4.4 Greeting "Welcome back + time away": `TurnJson` has no time-away field, so the toast is "Welcome back — {name} missed you".
- **Addition:** a first-hatch toast. When Phase 1's handshake saw `no_kitten` and the first feed then succeeds, one `frame --json` names the new kitten.

## Review Focus

1. **Hostile `/purr-rename` input.** Empty, whitespace-only, over 32 characters, control characters (ESC, newline, BEL), quotes, backslashes and emoji. Expected: the first four answer a usage/limit message **without running the binary**; quotes, backslashes and emoji go through as one argv element and come back in `message`. Pinned in Task 2.2.
2. **A cooldown or empty wallet is not an error.** `ok: true` with `result: 'cooldown' | 'insufficient_coins'` shows the binary's message as normal text with no `exitCode`. Only `result: 'error'` or a failed run sets `exitCode: 1`. Pinned in Task 2.2.
3. **Old card/stats rows after a reload or newer runs.** A transcript row whose key is not in `outputs` (module reloaded, or evicted beyond 20) must fall back to `next(e)` (plain text). A newer `/purr-stats` must not repaint an older row with newer numbers. Pinned in Task 2.3.
4. **Narrow surfaces.** The card is about 46 columns of box drawing. On a viewport narrower than the widest line (mobile), the render hook returns `next(e)` instead of a wrapped, garbled box. Pinned in Task 2.3.
5. **Unknown future celebration kinds** (the binary adds `v:1`-compatible variants). Expected: no toast and no throw. Pinned in Task 2.1.

**Model:** sonnet

**Files:**

- Test: `mod/hooks/celebrate.test.ts`

**Interfaces:**
- Consumes: `FeedJson`, `TurnJson`, `FrameJson`, `CelebrationKind`, `runJson`, `Runtime`, `PurrOptions.toastStreaks`.
- Produces: `KittenId = { name: string; level: number; stage: string; rarity: string; breed: string }`, and `Runtime.kitten: KittenId | null` (null = unknown). `Runtime.hadNoKitten: boolean` is set by `onSessionStart` when the handshake returned `ready` with `frame === null`. `onSessionStart` seeds `rt.kitten` from a handshake frame.
- Produces: `celebrationToast(kind: string | null, ctx: { name: string; level: number; total: number; toastStreaks: boolean }): { text: string; notify: boolean } | null`. This is a pure function, and its texts are exact:

| kind | text | notify |
|---|---|---|
| `LevelUp` | `{name} reached level {level} ✦` | no |
| `EvolvingYoung` | `{name} evolved into a young cat!` | **yes** |
| `EvolvingAdult` | `{name} evolved into an adult cat!` | **yes** |
| `MilestoneCenturion` | `100 tool calls together — Centurion` | no |
| `MilestoneVeteran` | `500 tool calls together — Veteran` | no |
| `MilestoneMaster` | `1000 tool calls together — Master` | no |
| `MilestoneLegendary` | `{floor(total/1000)*1000} tool calls together — Legendary` | **yes** |
| `Streak` | `5-call streak — {name} is on fire` (only when `toastStreaks`, else `null`) | no |
| `RandomDrop` | `{name} found +10¢` | no |
| `Greeting` | `Welcome back — {name} missed you` | no |
| `null`, `'None'`, or any other string | `null` | — |

  `{name}` falls back to `Your kitten` when it is unknown. The numbers mirror `events.rs` (`STREAK_TRIGGER = 5`, `RANDOM_DROP_REWARD = 10`, milestone watermarks 100/500/1000/every 1000 from 2000). If those constants change, these strings change with them.
- Produces: `announce($, rt, kind: string | null, total?: number): void`. It calls `celebrationToast`. When the result is non-null it calls `$.ui.toast(text)`, and when `notify` is set it also calls `void $.ui.notify(text, { title: 'Purrgotchi' }).catch(() => {})`. It never throws.
- Produces: `onFeedResult($, rt, r: FeedJson): Promise<void>`. It updates `rt.kitten.level/stage` and then, in order:
  - If `rt.hadNoKitten`: set `rt.hadNoKitten = false` and run `frame --json`. On success, set `rt.kitten` and toast `{name} hatched — a {rarity} {breed}!`. This hatch toast **replaces** any celebration in the same result.
  - Otherwise: `announce($, rt, r.celebration, r.total_tool_calls)`.
- Produces: `onTurnResult($, rt, r: TurnJson): void`, which calls `announce($, rt, r.celebration)`.

### Task 2.2: Action commands: `/purr-pet`, `/purr-play`, `/purr-treat`, `/purr-rename`, `/purr-hatch`

**Model:** sonnet

**Files:**
- Create: `mod/hooks/commands.ts`
- Modify: `mod/hooks/session.ts` (call `registerCommandNames` after the handshake), `mod/hooks/register.tsx`, `mod/hooks/testkit.ts`
- Test: `mod/hooks/commands.test.ts`

**Interfaces:**
- Consumes: `runJson`, `TIMEOUT.command`, `ActionJson`, `isError`, `ready`, `Runtime`, `PurrOptions.devCommands`, `rt.kitten`.
- Produces: `CommandName = 'purr-pet' | 'purr-play' | 'purr-treat' | 'purr-rename' | 'purr-card' | 'purr-stats' | 'purr-hatch'`.
- Produces: `COMMANDS: readonly { name: CommandName; description: string; argumentHint?: string; dev?: true }[]`, with these exact descriptions:
  - `purr-pet` "Pet the kitten (+bond)"
  - `purr-play` "Play with the kitten (starts a playground scene)"
  - `purr-treat` "Give the kitten a treat (costs coins)"
  - `purr-rename` "Rename the kitten", hint `<name>`
  - `purr-card` "Show the kitten's trading card"
  - `purr-stats` "Show the kitten's stats"
  - `purr-hatch` "Hatch a new kitten (dev)", hint `[--rarity r] [--breed "B"] [--shiny]`, `dev: true`
- Produces: `registerCommandNames($, rt): Promise<void>`. It registers every non-dev entry (plus dev entries when `devCommands`), each in its own try/catch. It runs from `onSessionStart` regardless of binary status.
- Produces: `NOT_READY_TEXT(status: BinaryStatus): string`. `missing` gives the not-found sentence (Global Constraints), and `outdated` gives "Purrgotchi binary {version} is too old for this mod — rebuild: `cargo install --path rust`".
- Produces: `validateName(raw: string): { ok: true; name: string } | { ok: false; text: string }`. The input is trimmed.
  - Empty gives `Usage: /purr-rename <name>`.
  - More than 32 characters (count with `[...name].length`) gives `Names are limited to 32 characters.`
  - Any `\p{Cc}` character gives `Names can't contain control characters.`
- Produces: `runAction($, rt, verb: 'pet' | 'play' | 'treat'): Promise<{ text: string; isError: boolean; result?: ActionJson }>`. It runs `[bin, verb, '--json']` through `rt.serial`.
  - `json` with `ok: true` (any `result`) gives `{ text: message, isError: false }`.
  - `json` with `ok: false` gives `{ text: message, isError: true }`.
  - `failed` gives `{ text: 'The kitten is unreachable right now (purrgotchi failed).', isError: true }`, plus a debug log of the reason.
  - Phase 3's pane buttons call this same function.
- Produces: `parseHatchArgs(args: string): { ok: true; argv: string[] } | { ok: false; text: string }`. The tokenizer supports double-quoted values. It accepts only `--rarity <common|uncommon|rare|epic|legendary>`, `--breed <name>` and `--shiny`; anything else gives the usage text. The binary validates breed names and exits 1 with its own message.
- Produces the `command.run` handlers registered in `registerCommands(on, rt)`, one `on('command.run', { command: name }, …)` per command. Each returns a `CommandRunResult`:
  - `purr-pet`, `purr-play`, `purr-treat` return `{ text, exitCode: isError ? 1 : undefined }` from `runAction`.
  - `purr-rename` calls `validateName(e.args)`. On failure it returns `{ text }` without running the binary. Otherwise it runs `[bin, 'rename', name, '--json']`: the name is a separate argv element, with **no shell**. On `ok` it returns `message` and sets `rt.kitten.name = result.name`; on error it returns `message` with `exitCode: 1`.
  - `purr-hatch` is registered only when `devCommands`. It calls `parseHatchArgs`, then runs `[bin, 'hatch', ...argv]` (plain run, because hatch has no `--json`) through `runJson`'s sibling `runRaw($, bin, args, init)`. Add `runRaw` to `binary.ts`: it returns `{ exitCode, stdout, stderr } | { failed: string }` and never throws.
    - Exit 0: refresh `rt.kitten` via `frame --json` and return `Hatched {name} — {rarity} {breed}.` Task 2.3 adds the card render for this row.
    - Non-zero: return the first stderr line with `exitCode: 1`.
  - Every handler starts with `if (!ready(rt)) return { text: NOT_READY_TEXT(rt.status), exitCode: 1 }`.

### Task 2.3: `/purr-card`, `/purr-stats` and the `CommandOutput` renderer

**Model:** sonnet

**Files:**
- Create: `mod/hooks/lines.tsx`, `mod/hooks/output.tsx`
- Modify: `mod/hooks/commands.ts`, `mod/hooks/atoms.ts`, `mod/types/index.d.ts`, `mod/hooks/register.tsx`
- Test: `mod/hooks/output.test.tsx`

**Interfaces:**
- Consumes: `LinesJson`, `FrameJson`, `Span`, `runJson`, `update`, `read`, `$.ui.resolve(e)`.
- Produces: `OutputEntry = { key: string; lines: Span[][] }`, plus the atom `outputsAtom = atom({ plugin: PLUGIN, key: 'outputs' } as const, [] as OutputEntry[])`. Declare `outputs: OutputEntry[]` in `PluginState`.
- Produces: `outputKey(command: string, text: string): string`, which is `` `${command}\u0000${text}` ``. `OUTPUT_CAP = 20`: keep the newest 20, replacing any existing entry with the same key.
- Produces: `kittenSummary(f: FrameJson | null, fallback: string): string`, which gives `{name} — lv {level} {stage} {breed}, {coins}¢, bond {bond}, mood {mood}`. The texts carry the current numbers, so a later run with different numbers gets a different key and older rows keep their own content.
- Produces the command handlers in `commands.ts`:
  - `purr-card` runs `card --json` and `frame --json` in parallel (both read-only; no `serial`). On `ok`, it `update`s `outputsAtom` with `{ key: outputKey('purr-card', text), lines }` and returns `{ text }`, where `text = kittenSummary(frame, 'Purrgotchi card')`.
  - `purr-stats` does the same with `stats --json` and the fallback `'Purrgotchi stats'`.
  - `no_kitten` gives `No kitten yet — it hatches on your first tool call.` (no `exitCode`).
  - A failure gives the unreachable text with `exitCode: 1`.
  - `purr-hatch` (dev): after a successful hatch, also run `card --json` and store it under the hatch row's key.
- Produces from `lines.tsx`:
  - `lineWidth(line: Span[]): number`, the sum of `[...span.text].length`.
  - `renderLines(els: { Box; Text }, lines: Span[][]): RenderElement`. It returns a `Box flexDirection="column"`. Each line is one `Text` whose children are one `Text` per span: `color={span.fg}`, `bold={span.bold}`, `dimColor={span.dim}`, and `mono` (the terminal ignores `mono`; desktop draws monospace). An empty line renders as `Text` with a single space.
- Produces from `output.tsx`: `registerOutputs(on)`, which registers `on('ui.render', { component: 'CommandOutput', props: { command } }, …)` for each of `purr-card`, `purr-stats` and `purr-hatch`.
  - If `e.props.isErrored`, return `next(e)`.
  - `entry = (await read($, outputsAtom)).find(x => x.key === outputKey(e.props.command, e.props.text))`. If it is absent, return `next(e)`.
  - If `e.viewport?.columns` is known and `< max(lineWidth)`, return `next(e)`.
  - If `e.surface` is not one of `terminal`, `desktop`, `vscode` or `mobile`, return `next(e)` (an unknown surface).
  - Otherwise return a `Box flexDirection="column"`: one dim `Text` with `e.props.text` (keeps the summary visible), then `renderLines`.
