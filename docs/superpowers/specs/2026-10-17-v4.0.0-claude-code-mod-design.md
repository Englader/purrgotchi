# Purrgotchi as a Claude Code mod — design

**Status:** proposal / starting point for implementation
**Date:** 2026-10-17
**Target:** v4.0.0
**Verified against:** Claude Code 2.1.302 (mods API is early access and moves between releases — the engine's generated `claude-code.d.ts` is the authority, not this doc)

---

## 1. Why

Today Purrgotchi is wired into Claude Code the "classic" way:

- `install.sh` uses `jq` to merge three entries into `~/.claude/settings.json`:
  `statusLine` → `purrgotchi statusline` (with `refreshInterval: 1`), `PostToolUse` → `purrgotchi feed`, `UserPromptSubmit` → `purrgotchi turn`.
- Interactive verbs (`pet`, `play`, `treat`, `card`, `stats`, `rename`, `hatch`) are only reachable from a shell, via the optional `purr` wrapper.
- Everything the kitten shows has to fit inside the statusline, which is re-run as a fresh process **every second** just so the sprite animates.
- Celebrations (level-up, evolution, milestones, streaks, drops, greeting) only exist as a few statusline frames gated by `levelup_renders_remaining` + `CELEBRATION_TICK_SECS`. If you're not looking at the HUD in that window, you miss them.
- LLM quips need the user's own provider key (Anthropic / Gemini / OpenAI) and a detached `react` worker that re-reads the transcript file.

**Mods** are Claude Code's new extension type: a small TypeScript/TSX module (`register(on, options)`) that hooks engine events (`tool.call`, `prompt.submit`, `session.start`, `session.measure`, `turn.complete`, `ui.render`, …), can draw UI (panes, a band above the prompt, status entries, toasts), register real slash commands and tools, run host commands (`$.process.run` / `$.process.spawn`), and call the session's own model (`$.model.complete`). They run in the terminal and in the desktop app's Code tab, with the same machine access as Claude Code (no sandbox). They're installed like plugins (`/plugin install`), and can be disabled per-mod via `/plugin` or all at once with `claude --safe-mode`.

Almost every pain point above maps onto a mod feature. This doc is the plan for that.

## 2. Goals / non-goals

**Goals**

1. Hooks without touching `settings.json` — the mod owns `feed` / `turn` wiring.
2. Real slash commands: `/purr:pet`-style commands instead of a shell wrapper.
3. A live kitten pane (sprite + playground scenes), driven by a timer, not a 1 Hz process respawn.
4. Toasts (and optionally native notifications) for milestones, level-ups, evolutions, streaks, drops, greetings.
5. Install via `/plugin install purrgotchi --marketplace Englader/purrgotchi` — no `jq`, no settings backup dance, no restart.
6. Keep the Rust binary as the **single source of truth** for state, game rules, sprites and rendering. The mod is a thin shell.

**Non-goals (for v4.0.0)**

- Porting game logic to TypeScript. `state.rs`, `bond.rs`, `events.rs`, `identity.rs`, `hatch.rs`, `sprites.rs` stay Rust. The existing ~10k lines and their tests are the asset.
- Dropping the classic statusline. It stays as an optional/fallback path (e.g. for people who don't want mods, or other harnesses).
- Mobile-specific UI. We draw with portable elements (`Box`, `Text`, `Button`) so the desktop/mobile surfaces degrade sanely, but terminal + desktop Code tab are the targets.

## 3. Architecture

```
┌──────────────────────── Claude Code (engine) ────────────────────────┐
│  events: session.start · tool.call · prompt.submit · session.measure │
│          turn.complete · command.run · ui.render · session.end        │
└───────────────┬──────────────────────────────────────────────────────┘
                │  $ (engine interface)
┌───────────────▼──────────── mod/ (TypeScript) ───────────────────────┐
│ register.tsx                                                          │
│  ├─ hooks: feed / turn wiring                                         │
│  ├─ commands: /pet /play /treat /card /stats /rename /hatch          │
│  ├─ pane "kitten": sprite + playground, $.clock.every tick            │
│  ├─ band (optional): compact HUD from session.measure                 │
│  └─ toasts: celebration events from the binary's JSON                 │
│  state: $.state atoms (frame, last event); nothing durable            │
└───────────────┬──────────────────────────────────────────────────────┘
                │  $.process.run(['purrgotchi', …, '--json'])
┌───────────────▼──────────── rust/ (unchanged core + JSON surface) ───┐
│ state.json under ~/.claude/purrgotchi/ (locked_update) — the truth   │
└──────────────────────────────────────────────────────────────────────┘
```

The rule: **the mod never owns durable state.** `~/.claude/purrgotchi/state.json` (behind `state::locked_update`) remains the only store, so the classic statusline, the `purr` CLI and the mod can all coexist and agree. `$.state` atoms in the mod only hold *view* state (current frame, latest celebration to toast) and are rebuilt from the binary on every `session.start` / reload.

### 3.1 Required changes in the Rust binary: a machine-readable surface

The binary currently only speaks "human": statusline output is raw 24-bit ANSI (`\e[38;2;r;g;bm…`), `pet`/`treat`/`play` print prose, and `feed` prints nothing. Mod UI elements don't interpret ANSI — `Text` takes a `color` prop instead. So v4 adds a `--json` mode. Proposed contract (new `rust/src/json.rs`, serde structs, versioned):

| Command | Today | v4 `--json` output |
|---|---|---|
| `feed` | silent | `{ "v":1, "celebration": "LevelUp" \| null, "level", "stage", "coins", "total_tool_calls", "drop": bool }` — the `apply_feed_dispatch` result |
| `turn` | silent, reads stdin payload | same as today + `{ "v":1, "celebration": "Greeting" \| null, "react_spawned": bool }` |
| `pet` / `play` / `treat` / `rename` | prose to stdout | `{ "v":1, "message": "<the same prose>", "ok": bool, …result fields }` |
| `stats` / `card` | ANSI/box text | `{ "v":1, "lines": [ Span[] ] }` (see below) **or** plain text with `--plain` |
| **new** `frame` | — | `{ "v":1, "sprite": [Span[]…6 rows], "speech": Span[], "scene": {...} \| null, "celebration": … }` for `--width N --tick T` |

`Span = { "text": string, "fg"?: "#rrggbb", "bold"?: bool, "dim"?: bool }`. This is a straight refactor of `colors.rs` + `render.rs`: today the colour constants are concatenated into strings; v4 builds a `Vec<Span>` and has two printers (`ansi` for the statusline, `json` for the mod). Statusline output must stay byte-identical — add a golden test before refactoring.

Celebration detection already lives in pure helpers (`detect_celebration`, `events::detect_milestone`, `detect_streak`, `roll_random_drop_with_seed`) and `apply_feed_dispatch` already decides one winning `CelebrationKind`. Returning that kind is the whole "toast" feature on the Rust side.

### 3.2 Finding the binary

`$.process.run` takes an argv, no shell. Resolution order in the mod:

1. `userConfig.binaryPath` (string, optional) — explicit path, e.g. `C:/…/purrgotchi.exe`.
2. `purrgotchi` on `PATH` — recommend `cargo install --path rust` in the README (puts it in `~/.cargo/bin`, works on Windows/Linux/macOS, no `.exe`-path special-casing as in the recent Linux install fix).
3. Neither → one toast on `session.start`: "Purrgotchi binary not found — set binaryPath in /config or run `cargo install --path rust`", and every hook becomes a no-op `next(e)`.

Validate once in `session.start` with `purrgotchi --version` and require a minimum version that has `--json` (4.0.0). Version-mismatch → same toast, hooks no-op.

## 4. Feature by feature

### 4.1 Hooks without touching settings.json

| Classic | Mod |
|---|---|
| `PostToolUse` `*` → `purrgotchi feed` | `on('tool.call', async ($, e, next) => { const r = await next(e); await feed($); return r })` |
| `UserPromptSubmit` → `purrgotchi turn` (payload on stdin) | `on('prompt.submit', …)` → `$.process.run([bin,'turn','--json'], { stdin: JSON.stringify({ session_id, transcript_path }) })` |

Notes:
- `feed` doesn't read stdin at all today, so it's a bare `run([bin, 'feed', '--json'])`. `turn` reads `session_id` and `transcript_path` from stdin; `$.process.run` accepts `stdin`, so keep the payload contract and build it from what the mod knows. Where `prompt.submit` doesn't expose `transcript_path` directly, `classic.UserPromptSubmit` (the classic hook's stdin, exposed as an event) does — hooking that is the lowest-friction port.
- Always call `next(e)` first and never `deny`. These hooks must be **observers**: a Purrgotchi failure must never block a tool call or a prompt. Wrap the process call in try/catch; `.catch(($, e, next) => next(e))` on registration as a belt-and-braces.
- Cost: one process spawn per tool call — same as today. The binary is fast (ms), but `$.process.run` time counts against the hook. Option if it shows up: batch — increment an atom per tool call and flush `feed --count N` on `turn.complete` or a 2 s `$.clock.every`. That needs a `--count` flag on `feed` (loop `apply_feed_dispatch` N times, return the highest-priority celebration). Measure first.
- **Double-feeding during migration.** If a user has both the old `settings.json` hooks and the mod, every tool call feeds twice. The mod checks on `session.start` (read `~/.claude/settings.json` via `$.fs`, look for `purrgotchi` in `hooks.PostToolUse` / `UserPromptSubmit`) and toasts: "Old Purrgotchi hooks still in settings.json — run `bash install.sh --uninstall-hooks`". Add that flag to `install.sh` (reverse jq filter, same backup logic). Keep the `statusLine` entry by default; it doesn't double-count anything.

### 4.2 Real slash commands

Register in `session.start` with `$.command.register({ name, description, argumentHint? })`, answer in `command.run` with `{ text }`. Installed plugin commands are namespaced by the plugin name, so they'll show as `/purrgotchi:pet` etc. — fine, and the namespace keeps `/stats` from colliding with anything built-in.

| Command | Calls | Output |
|---|---|---|
| `/pet` | `pet --json` | `message` as the command's text; toast if bond tier changed |
| `/play` | `play --json` | `message`; also starts a playground scene → nudge the pane |
| `/treat` | `treat --json` | `message` |
| `/card` | `card --json` | draw the card via a `CommandOutput` `ui.render` hook as coloured `Text` spans (inline in the transcript, like a built-in command's output) |
| `/stats` | `stats --json` | same `CommandOutput` treatment |
| `/rename <name>` | `rename <name> --json` | `message`; exit code 1 → error text |
| `/hatch [--rarity r] [--breed b] [--shiny]` | `hatch …` | debug/dev only — consider gating behind a `userConfig.devCommands` boolean |
| `/kitten` | — | opens / focuses the pane (§4.3) |

Important: `{ text }` from `command.run` is **also read by the model** (the `CommandOutput` row). Keep messages short and in-character; that's a feature (Claude can comment on the kitten) but don't dump the full card into context — return a one-line summary as `text` and draw the full card in the `CommandOutput` render hook.

### 4.3 Live kitten pane

- `$.ui.open({ id: 'kitten', title: 'Purrgotchi' })` from `/kitten`, and on `session.start` only where `e.viewport.isFullscreen` (i.e. it docks as a sidebar rather than pushing into the transcript).
- `on('ui.render', { component: 'Pane', requestId: 'kitten' }, …)` reads a `frame` atom and draws 6 sprite rows + speech row + a scene strip as `Text` with `color` per span, sized to `e.props.bodyColumns` (not `COLUMNS` — `playground::strip_width()` gets a `--width` override).
- Animation: `$.clock.every(1000, tick)` started in `session.start` → `run([bin,'frame','--json','--width',W])` → `update($, frame, () => json)`. The write redraws only that pane. This replaces `refreshInterval: 1`.
- Better (phase 3): `purrgotchi serve` — one long-lived process via `$.process.spawn` writing one JSON frame per line; the mod parses the stream and updates the atom. One spawn per session instead of one per second. Needs care: the stream's loop is the child's life, so it must be owned by a long-lived context (`session.start` + timers), and the child must exit when stdin closes.
- Buttons in the pane: `[ pet ]  [ treat ]  [ play ]` with hotkeys `p` / `t` / `y` → same code path as the commands. Pane-local, so they work without typing.
- Celebration frames (`get_celebration_sprite`) show in the pane for their duration; `CELEBRATION_TICK_SECS` gating moves from "statusline render count" to wall-clock in `frame`.
- Terminal-only extra (later): sprites as an `Image`/`Raster` (kitty graphics) instead of ASCII. Only if someone actually wants pixel art; ASCII works on every surface.

### 4.4 Toasts for milestones, level-ups, evolutions

Every `feed --json` / `turn --json` returns the winning `celebration`. Map → `$.ui.toast`:

| `CelebrationKind` | Toast | Also `$.ui.notify`? |
|---|---|---|
| `LevelUp` | "Thalia reached level 12 ✦" | no |
| `EvolvingYoung` / `EvolvingAdult` | "Thalia evolved into a young cat!" | **yes** — rare, worth a native notification |
| `MilestoneCenturion` … `MilestoneLegendary` | "100 tool calls together — Centurion" (etc.) | Legendary only |
| `Streak` | "5-call streak" | no (frequent — consider `userConfig.toastStreaks: false` default) |
| `RandomDrop` | "Found +10 coins" | no |
| `Greeting` | "Welcome back" + time away | no |

Keep the statusline/pane celebration frames too — toasts are additive. One toast per plugin replaces the previous one on the bar, so bursts self-limit. `$.ui.notify` respects the user's notification channel setting; never call it for frequent events.

### 4.5 HUD: band above the prompt (optional) and status entry

The 7-row HUD is the statusline. Two mod-native options, both fed by data the engine already pushes:

- `on('session.measure', …)` gives `{ context, rateLimits, cost, changed }` — context fill %, the 5 h / 7 d rate-limit windows, and session cost — *pushed* after every main-thread turn and whenever a window moves a point. `$.session.usage()` answers the same on demand. That's everything `payload.rs` parses from statusline stdin (model name aside — from `$.session`/settings).
- Mood is a function of context pressure (`mood.rs`): feed `context.percent` to `frame --context-pct N` instead of the stdin payload.
- `cost_acc::accumulate_from_payload` (lifetime cost tally) moves to a `session.measure` hook that calls `purrgotchi cost --session <id> --total <usd>` when `changed` includes `cost`.
- **Band** (`ui.render` on `AbovePrompt`): a 1–2 row compact HUD (mood face + level + coins + 5h bar). Opinion: make it opt-in. The pane is the kitten's home; a permanent band costs vertical space on every screen.
- **Status entry** (`$.ui.status(text)`): one plain line, e.g. `=^.^= Thalia Lv12 · 340¢`. Cheap and always visible — good default when the pane is closed.

Recommendation: v4 ships pane + status entry; band behind `userConfig.band`. The classic statusline stays installable for people who want the full cyberpunk HUD.

### 4.6 LLM quips via the session's own model (phase 3, big simplification)

`react.rs` + `llm/{anthropic,gemini,openai,select,transport}.rs` (~1,100 lines) exist to call a provider with the user's key from a detached worker that re-reads the transcript. A mod can call `$.model.complete({ model, prompt, system })` on the **session's own client** — no API key, no `.env`, no detached process, no transcript parsing. On `turn.complete` (which has the turn's result) roll `should_fire_react`, build the prompt with `purrgotchi quip-prompt --json` (persona + mood + recent event, from `speech.rs`), call the model, then `purrgotchi quip-store "<text>"` into `quip_cache`.

Caveats: costs the user's own usage (use the smallest model, short `maxTokens`, and keep the existing probability gate); `$.model.complete` always resolves (check `isAnswered`), so failure falls back to the static phrase pool exactly as today. Keep the Rust providers for the classic/no-mod path; don't delete them in v4.

### 4.7 Install & distribution

Make the repo itself a marketplace:

```
.claude-plugin/marketplace.json   # { name: "purrgotchi", owner: {...}, plugins: [{ name: "purrgotchi", source: "./mod" }] }
mod/
  .claude-plugin/plugin.json      # name, version, description, userConfig, "types"
  hooks/hooks.json                # { "modules": ["./register.tsx"] }
  hooks/register.tsx
  hooks/*.ts                      # binary.ts (resolve + run + JSON parse), commands.ts, pane.tsx, toasts.ts
  hooks/*.test.ts                 # claude plugin test
  types/index.d.ts                # PluginState contract for $.state atoms
```

User flow becomes:

```bash
git clone https://github.com/Englader/purrgotchi && cd purrgotchi
cargo install --path rust          # puts `purrgotchi` on PATH
```
then at a Claude Code prompt:
```
/plugin install purrgotchi --marketplace Englader/purrgotchi
```
Desktop app: `+` → Plugins → Add marketplace `Englader/purrgotchi` → Add plugin. No `jq`, no settings backup, no restart (hooks are live immediately).

`userConfig` (shown in `/config`, stored under `pluginConfigs.purrgotchi`):

| key | type | default | purpose |
|---|---|---|---|
| `binaryPath` | string | `""` | explicit binary path |
| `openPaneOnStart` | boolean | `true` | auto-open pane when fullscreen |
| `band` | boolean | `false` | compact HUD above prompt |
| `toastStreaks` | boolean | `false` | streak toasts are noisy |
| `quips` | string, options `off`/`session-model`/`own-key` | `own-key` (v4.0), `session-model` (v4.1) | §4.6 |
| `devCommands` | boolean | `false` | exposes `/hatch` |

`install.sh` stays for the classic path and gains `--uninstall-hooks` (§4.1). README gets two install sections: "As a mod (recommended)" and "Classic statusline".

Stretch: ship prebuilt binaries (GitHub Releases, cargo-dist) so users don't need Rust; the mod downloads nothing itself — README points at the release, `binaryPath` points at it.

## 5. Phased plan

| Phase | Scope | Done when |
|---|---|---|
| **0 — Rust JSON surface** | `json.rs`, `Span` refactor of `colors.rs`/`render.rs` with golden test for statusline bytes, `--json` on `feed`/`turn`/`pet`/`play`/`treat`/`rename`/`stats`/`card`, new `frame --width --tick --context-pct`, `install.sh --uninstall-hooks` | `cargo test` green, statusline output byte-identical, JSON schemas covered by tests |
| **1 — Mod skeleton + hooks** | marketplace.json, `mod/` scaffold, binary resolution + version check, `tool.call` → feed, `prompt.submit`/`classic.UserPromptSubmit` → turn, double-feed detection | `claude plugin validate mod` clean; `claude plugin test mod` covers feed/turn; counters move in a real session with settings hooks removed |
| **2 — Commands + toasts** | 7 commands + `/kitten`, `CommandOutput` renderer for card/stats, celebration → toast/notify map | each command tested on `terminal` and `desktop` surfaces in `claude plugin test` |
| **3 — Pane** | pane + 1 s clock tick, buttons, `session.measure` → mood/context, status entry, optional band | kitten animates in the pane; playground scenes fit `bodyColumns` |
| **4 — Polish** | `serve` streaming mode, `$.model.complete` quips, cost accumulation via `session.measure`, README/CHANGELOG, v4.0.0 tag | install from a fresh machine via `/plugin install` works end to end |

## 6. Testing

- **Rust:** keep the existing unit tests; add golden tests for statusline ANSI output (before the Span refactor) and serde round-trip tests for every JSON output.
- **Mod:** `claude plugin test mod/` runs `*.test.ts` against the real engine. Mock `$.process.run` results with fixture JSON (no binary needed in tests). Loop UI tests over `['terminal','desktop'] as const`. Test the failure paths explicitly: binary missing, non-zero exit, malformed JSON, timeout → hook passes `next(e)` and the tool call/prompt is unaffected.
- **Type-check:** `tsc -p mod` once the engine has laid `.claude-plugin/types/` (it writes a `tsconfig.json` the mod's own extends).
- **Manual:** a session with `--debug` — skipped hooks and refused UI trees are logged there with reasons.

## 7. Risks & open questions

1. **API churn.** Mods are early access; the event/`$` surface changes between releases. Pin the Claude Code version range in the README; regenerate types on each bump rather than hand-editing.
2. **No sandbox.** The mod (and thus Purrgotchi) runs with full Claude Code privileges. Keep the mod's own surface minimal: it only ever runs our binary, with fixed argv, never user/model-provided strings except `/rename`'s argument (pass as a separate argv element — no shell, so no injection, but still length-limit it).
3. **Hook latency on Windows.** Process spawn is slower on Windows than Linux. If `feed` per tool call is noticeable, do the batched `feed --count N` (§4.1).
4. **Concurrency.** Multiple sessions + the classic statusline + the mod all hit `state.json`. `state::locked_update` already serialises writers; confirm `frame` is read-only and cheap under the lock (it advances playground/celebration timers today inside `statusline::run` — split "advance" from "read" so the pane and the statusline don't both tick celebrations).
5. **`transcript_path` in mod events.** Verify exactly which event in the current build carries it; `classic.UserPromptSubmit` is the safe bet. Remove the need entirely with §4.6.
6. **Desktop surface.** The desktop Code tab draws panes natively; check how 24-bit colour spans and monospace alignment render there (`Text mono`). The sprite art assumes a monospace grid.
7. **Command namespacing.** Confirm whether commands show as `/pet` or `/purrgotchi:pet` in the current build and document whichever it is.
8. **Statusline + mod coexistence.** Both read the same state; that's intended. But two renderers advancing `levelup_renders_remaining` is a bug — see (4).

## 8. Getting started in a container (checklist)

```bash
# toolchain (verified 2026-10-17 in a Claude Code cloud container: cargo/rustc 1.97, Claude Code 2.1.302, Node 22)
cd rust && cargo build --release && cargo test && cd ..

# isolate state while developing — never touch your real kitten
export HOME=$(mktemp -d)        # or point paths.rs at PURR_STATE_DIR if you add that override
./rust/target/release/purrgotchi feed && ./rust/target/release/purrgotchi stats

# mod development
claude plugin validate mod
claude plugin test mod
claude --plugin-dir ./mod --debug      # hot-reloads on save in an interactive session
```

Suggested first task: Phase 0's golden test for statusline output (so the Span refactor can't silently change the HUD), then `feed --json`. Both are small, pure-Rust, and unblock everything else.

Worth adding while in there: a `PURR_STATE_DIR` env override in `paths.rs` so tests and the mod's test fixtures never need to fake `HOME`.
