# v3.6.3 — Maintenance: shared LLM transport, dead-code cleanup, key-hint UX

**Date:** 2026-04-28
**Version:** 3.6.2 → 3.6.3 (patch)
**Scope:** Four small, related hygiene fixes shipped as one maintenance release.

## Background

After v3.6.2 shipped the react-watchdog hotfix, four loose ends remain in the
codebase. None block usage; together they reduce duplication, prevent a future
flush-contract regression, and improve first-run UX for new users.

1. **LLM provider duplication.** `anthropic.rs`, `gemini.rs`, and `openai.rs`
   each contain identical `ureq::AgentBuilder` setup, identical
   `CONNECT_TIMEOUT_SECS`/`READ_TIMEOUT_SECS` constants, identical
   `Err(ureq::Error::Status/Transport)` → `LlmProviderError` mapping, and a
   near-identical `truncate_body` helper. Roughly 50 lines of logic
   duplicated 3× = ~150 lines of avoidable surface.
2. **Dead test helper.** `rust/src/quip_cache.rs:67` defines
   `#[cfg(test)] pub fn read()` with zero callers anywhere in the codebase.
   It produces a `dead_code` warning under `cargo test --no-run`.
3. **Implicit flush contract.** The v3.6.2 watchdog calls `debug::log` then
   `std::process::exit(0)`. The breadcrumb survives only because
   `debug::log_inner` keeps the `File` unbuffered — there's no `BufWriter`
   wrapping, so close-on-Drop is a synchronous flush. Nothing in `debug.rs`
   communicates that this is intentional, so a future "let's add buffering
   for performance" refactor would silently break the watchdog's
   observability guarantee.
4. **Silent first-run.** A user who runs `purrgotchi hatch` without
   `PURR_LLM_PROVIDER` set in `.env` gets a kitten with a static personality
   blurb and no react quips, with no signal that LLM-powered speech is even
   possible. Discoverability is poor.

## Goals

- Eliminate the 3-way duplication in the LLM provider modules.
- Remove the `quip_cache::read` dead-code warning.
- Make the watchdog's flush dependency explicit and refactor-resistant.
- Surface a one-time hint after `hatch` when no LLM provider is configured.
- Ship as a single small maintenance release with no behaviour change on
  any existing happy path.

## Non-goals

- Changing the public `LlmProvider` trait or `LlmRequest`/`LlmResponse`
  shapes.
- Cost tracking for non-Anthropic providers (deferred — user explicitly
  opted out for this release).
- OpenAI reasoning-model `max_completion_tokens` compatibility (deferred).
- Friendlier hints on commands other than `hatch` (would risk nagging on
  the statusline hot path).

## Design

### Component 1: `rust/src/llm/transport.rs`

New private helper module under `llm/`. Exposes two functions and one
constant pair, all `pub(super)` (visible to sibling provider modules,
not to the rest of the crate).

```rust
//! Shared transport helpers for the three LLM provider impls.
//! Keeps timeout policy, agent construction, error mapping, and body
//! truncation in one place so the per-provider modules stay focused on
//! request shape and response parsing.

use std::time::Duration;
use crate::llm::LlmProviderError;

pub(super) const CONNECT_TIMEOUT_SECS: u64 = 10;
pub(super) const READ_TIMEOUT_SECS: u64 = 10;
const ERROR_BODY_MAX_CHARS: usize = 500;

/// Standard ureq agent for any LLM provider call. Identical across all
/// three impls today; centralized so policy tweaks (timeouts, future
/// proxy support) land in one place.
pub(super) fn build_agent() -> ureq::Agent {
    ureq::AgentBuilder::new()
        .timeout_connect(Duration::from_secs(CONNECT_TIMEOUT_SECS))
        .timeout_read(Duration::from_secs(READ_TIMEOUT_SECS))
        .build()
}

/// Map a ureq error into our normalized provider error.
///   Status(code, resp)  → Http(code, truncated body)
///   Transport(timeout)  → Timeout
///   Transport(other)    → Network(msg)
pub(super) fn map_ureq_error(e: ureq::Error) -> LlmProviderError {
    match e {
        ureq::Error::Status(code, response) => {
            let body = response.into_string().unwrap_or_default();
            LlmProviderError::Http(code, truncate_body(body))
        }
        ureq::Error::Transport(t) => {
            let s = t.to_string();
            if s.contains("timed out") || s.contains("timeout") {
                LlmProviderError::Timeout
            } else {
                LlmProviderError::Network(s)
            }
        }
    }
}

fn truncate_body(s: String) -> String {
    if s.chars().count() <= ERROR_BODY_MAX_CHARS {
        s
    } else {
        s.chars().take(ERROR_BODY_MAX_CHARS).collect()
    }
}
```

Each provider's `complete()` shrinks. The pattern in every provider:

```rust
// Before:
let agent = ureq::AgentBuilder::new()
    .timeout_connect(Duration::from_secs(CONNECT_TIMEOUT_SECS))
    .timeout_read(Duration::from_secs(READ_TIMEOUT_SECS))
    .build();
let t0 = std::time::Instant::now();
let resp = agent.post(URL).set(...).send_json(body);
let latency_ms = t0.elapsed().as_millis();
match resp {
    Ok(r) => { /* parse */ }
    Err(ureq::Error::Status(code, response)) => {
        let body = response.into_string().unwrap_or_default();
        Err(LlmProviderError::Http(code, truncate_body(body)))
    }
    Err(ureq::Error::Transport(t)) => {
        let s = t.to_string();
        if s.contains("timed out") || s.contains("timeout") {
            Err(LlmProviderError::Timeout)
        } else {
            Err(LlmProviderError::Network(s))
        }
    }
}

// After:
let agent = transport::build_agent();
let t0 = std::time::Instant::now();
let resp = agent.post(URL).set(...).send_json(body);
let latency_ms = t0.elapsed().as_millis();
match resp {
    Ok(r) => { /* parse */ }
    Err(e) => Err(transport::map_ureq_error(e)),
}
```

The per-provider `truncate_body` helpers and `CONNECT_TIMEOUT_SECS`/
`READ_TIMEOUT_SECS` constants get deleted from each provider file. Each
provider adds `use super::transport;` and `mod transport;` is declared
in `llm/mod.rs`.

**Tests:**
- Three new unit tests in `llm/transport.rs`:
  - `map_ureq_error_status_becomes_http` — needs construction of a
    `ureq::Error::Status` (or a stub via `MockResponse`); if that's
    awkward in tests, fall back to direct construction of the error
    response body and test `truncate_body` separately, plus an
    integration-style test that exercises the wiring.
  - `map_ureq_error_timeout_message_becomes_timeout` — synthesize a
    transport error whose `to_string()` contains "timed out".
  - `map_ureq_error_other_transport_becomes_network` — synthesize a
    transport error whose `to_string()` does NOT contain "timed out".
  - If `ureq::Error` construction is too closed for direct testing, add
    a `pub(super) fn map_transport_message(s: &str) -> LlmProviderError`
    helper that the public `map_ureq_error` calls into for the Transport
    arm. Test the helper directly with strings.
- One `truncate_body_caps_at_500_chars` test on the long-body path.
- Existing per-provider response-parse tests stay in their own files.

### Component 3: Flush contract comment in `debug.rs`

Add a one-line comment above the `let mut f = fs::OpenOptions::new()...`
block in `log_inner`:

```rust
fn log_inner(line: &str) -> std::io::Result<()> {
    let now = SystemTime::now().duration_since(UNIX_EPOCH).unwrap_or_default();
    let dir = paths::state_dir();
    fs::create_dir_all(&dir)?;
    // Intentionally unbuffered: react::run's watchdog calls debug::log
    // immediately before std::process::exit(0). Close-on-Drop is a
    // synchronous flush only because there is no BufWriter here.
    let mut f = fs::OpenOptions::new()
        .create(true)
        .append(true)
        .open(dir.join("debug.log"))?;
    writeln!(f, ...)?
}
```

This is a structural comment (the WHY behind the unbuffered choice),
not narrative. It survives the project's "no comments unless WHY is
non-obvious" preference because the contract is genuinely subtle.

### Component 4: Missing-key hint on hatch

After `hatch::run` writes the new state and prints its success message,
check whether an LLM provider can be selected. If
`llm::select::current_provider()` returns `Err`, print a single dim-cyan
hint line to stderr:

```
hint: set PURR_LLM_PROVIDER (and the matching API key in .env) to enable AI personality and react quips.
```

**Location:** in `hatch::run`, after the existing success print, before
return. Only fires when the LLM call was already going to fall back
(no `PURR_LLM_PROVIDER`, or set but corresponding API key missing).

**Why hatch only:** statusline runs every turn — adding a hint there
would be nag spam. Hatch runs once per kitten lifetime; missing the
hint that one time is a fair tradeoff.

**Why stderr:** keeps the hint out of any pipe-captured stdout that
shells or wrappers might consume.

**Color:** dim cyan (existing palette, used elsewhere for hints). If
the existing color constants don't include a "dim hint" variant, use
`C_CYAN` directly with no bold.

**Tests:**
- `hatch_prints_hint_when_provider_unset` — set the env so
  `current_provider()` returns `Err`, run hatch in a temp HOME, capture
  stderr, assert the hint substring is present. (Capturing stderr from
  inside the same process needs `gag` or manual `set_var`/`Stdio` —
  prefer extracting a pure helper `should_print_key_hint(provider_result)
  -> bool` and unit-test that. The actual print call doesn't need its
  own test.)
- `hatch_does_not_print_hint_when_provider_ok` — pure helper returns
  false when `Ok`.

## Error handling

- `transport::map_ureq_error` cannot fail — it always returns an
  `LlmProviderError`. Body extraction uses `unwrap_or_default()` to keep
  the existing tolerance.
- `should_print_key_hint` is pure. The hint print itself is best-effort
  (a stderr write failing is silently ignored — same pattern as
  `debug::log`).
