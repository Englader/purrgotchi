# v3.6.2 — React worker watchdog + error-log legibility

**Date:** 2026-04-28
**Version:** 3.6.1 → 3.6.2 (patch)
**Scope:** Two small, related fixes shipped as one hotfix.

## Background

### Problem 1: Detached react worker can zombie on Windows

`hooks::turn` spawns `purrgotchi react <transcript>` detached after a 1-in-5 dice
roll (`spawn::detached_self`). The worker calls the configured LLM provider via
`ureq`, which has per-operation timeouts (`timeout_connect`, `timeout_read`, ~10s
each). On Windows, those timeouts do not reliably fire end-to-end — TLS
handshake stalls, slow proxies, and provider rate-limiting can leave the process
waiting indefinitely.

The detached process holds an open file handle on `purrgotchi.exe` for as long as
it's alive. Once it stalls, `cargo build` cannot replace the binary on the next
rebuild ("Access is denied"). The user has hit this in real workflow; the
documented workaround is the rename trick (`ren purrgotchi.exe purrgotchi.exe.zombie`).

There is no upper bound on how long a stalled worker can live. The fix
introduces one.

### Problem 2: Three `dead_code` warnings in `LlmProviderError`

`rust/src/llm/mod.rs` defines:

```rust
pub enum LlmProviderError {
    AuthMissing,
    Http(u16, String),
    Network(String),
    Timeout,
    MalformedResponse(String),
}
```

The inner data on `Http`, `Network`, and `MalformedResponse` is constructed by
the providers but never read in production code (only inspected via auto-derived
`Debug` in tests). The release build emits three `dead_code` warnings.

The data is exactly what future-us wants when triaging `debug.log` ("was that a
429 or a 503?"). It should be made legible, not removed.

## Goals

- Eliminate the zombie failure mode by enforcing a wall-clock upper bound on
  every detached `purrgotchi react` invocation.
- Turn the three `dead_code` warnings into actually useful debug output.
- Ship as a single small hotfix (v3.6.2) with no behaviour change on the happy
  path.

## Non-goals

- Replacing or extending the existing per-operation HTTP timeouts.
- Adding a watchdog around the synchronous `hatch` LLM call. Hatch is foreground
  and the user can Ctrl-C; the zombie problem is exclusive to detached workers.
- Generalizing the watchdog into a reusable utility. There is exactly one
  detached worker today (`react`), and YAGNI applies.
- Cost tracking for non-Anthropic providers (separate concern, deferred).

## Design

### Component 1: React worker watchdog

**Location:** `rust/src/react.rs`, invoked at the top of `pub fn run(...)`.

**Behaviour:**

1. On entry to `react::run`, spawn a detached thread that sleeps for 30 seconds
   of wall-clock time, then writes a single debug-log line and calls
   `std::process::exit(0)`.
2. Normal completion: `run_inner` returns, `main` exits with code 0, the
   watchdog thread is killed by process exit before it ever wakes — no
   coordination needed.
3. Stalled completion: 30 seconds elapse, the watchdog wakes, logs
   `[llm] react fail reason=watchdog_timeout`, and force-exits the process.
   Any in-flight HTTP socket is closed by the OS as part of process teardown,
   freeing the binary handle.

**Pseudocode:**

```rust
pub fn run(transcript_path: &str) {
    spawn_watchdog(WATCHDOG_DEADLINE_SECS);
    let _ = run_inner(transcript_path);
}

const WATCHDOG_DEADLINE_SECS: u64 = 30;

fn spawn_watchdog(deadline_secs: u64) {
    std::thread::spawn(move || {
        std::thread::sleep(std::time::Duration::from_secs(deadline_secs));
        crate::debug::log("[llm] react fail reason=watchdog_timeout");
        std::process::exit(0);
    });
}
```

**Design choices:**

- **Duration: 30 seconds.** A successful Gemini/Anthropic call is ~1s; the
  legitimate worst case (cold TLS, slow first token) tops out at ~10s. 30s
  gives ~3× headroom — generous enough that any trip is a real bug, tight
  enough that a zombie clears within a single Pomodoro tick.
- **Exit code 0.** Consistent with the rest of `react::run`: every failure
  path is non-fatal and silent. The parent never reads the exit code (it
  doesn't `wait()`), so anything else would be a lie about severity.
- **Log before exit.** The log line flushes from the watchdog thread before
  `process::exit` tears down stdio. The line only appears when
  `PURR_DEBUG=1`; in production it costs nothing.
- **Detached thread, no cancellation.** When `main` returns normally, the
  process exits and the kernel reaps the watchdog thread. We don't need
  channels, atomics, or `JoinHandle::join` — the watchdog is fire-and-forget.

### Component 2: `LlmProviderError` Display impl

**Location:** `rust/src/llm/mod.rs`.

Add an `impl std::fmt::Display for LlmProviderError` that prints a one-line
human-readable summary including the carried data:

```
AuthMissing            → "auth missing"
Http(429, "...")       → "HTTP 429: <body, truncated>"
Network("dns ...")     → "network: dns ..."
Timeout                → "timeout"
MalformedResponse(...) → "malformed response: ..."
```

Switch the two existing `err={e:?}` debug-log call sites to `err={e}`:

- `rust/src/hatch.rs:201` — `[llm] hatch fail provider=... err={e:?}` → `err={e}`
- `rust/src/react.rs:325` — `[llm] react fail provider=... err={e:?}` → `err={e}`

This reads the previously-warned fields in production code, eliminating the
three `dead_code` warnings. `Debug` derive stays in place — tests still rely on
it for variant assertions.

## Error handling

The watchdog itself has no error path: `thread::spawn` either succeeds (and we
get a watchdog) or fails (and we proceed without one — best-effort, same
silent-degradation philosophy as everything else in `react`). We don't gate or
log the spawn result.

## Testing

### Unit tests (in `react.rs`)

- `watchdog_thread_fires_after_deadline` — extract a non-exiting variant of the
  watchdog body that sets an `AtomicBool` instead of calling `process::exit`,
  spawn it with a 50ms deadline, sleep 100ms, assert the flag is set. The
  exit-and-log wrapper is trivial enough to leave untested.

### Unit tests (in `llm/mod.rs`)

- `display_auth_missing_formats` — `format!("{e}")` on `AuthMissing` produces
  the expected lowercase summary.
- `display_http_includes_status_and_body` — `Http(429, "rate limit")` formats
  to a string containing both `429` and `rate limit`.
- `display_network_includes_message` — covers `Network`.
- `display_timeout_formats` — covers `Timeout`.
- `display_malformed_includes_message` — covers `MalformedResponse`.

### Out of scope

A real integration test for the zombie fix would require simulating a hung
HTTPS server on Windows and waiting 30 seconds — too slow for CI and brittle
across platforms. The fix is small enough that code review + manual smoke
verification on the user's machine is sufficient.

### Manual verification

1. Build release: `cargo build --release`.
2. Trigger `purrgotchi react` against a normal transcript with `PURR_DEBUG=1`;
   confirm the happy path still completes in ~1s with a quip written.
3. Confirm `debug.log` shows the expected `[llm] react ok ...` line and **no**
   `watchdog_timeout` line.
4. Confirm there are zero `dead_code` warnings in the release build output.
