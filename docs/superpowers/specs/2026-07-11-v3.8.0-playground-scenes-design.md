# v3.8.0 Playground Scenes — Design

**Date:** 2026-07-11
**Status:** Approved by user (architecture, scene catalog, captions, scheduling, prop style all confirmed)
**Target release:** v3.8.0

## Summary

Thalia gets a playground: the horizontal strip to the right of the HUD card, extending
to the terminal's right edge. At random intervals (every 2–5 minutes) she plays an
animated scene lasting 20–40 seconds — running, chasing a ball or butterfly, rolling,
pushing a yarn ball — rendered at 1 frame/second by the existing
`statusLine.refreshInterval = 1` re-render. `purr play` triggers a scene immediately.
When no scene is active, the statusline looks exactly as it does today.

## Goals

- Animated play scenes in the strip right of the card (columns 99+), rows 0–5,
  extending to the terminal's right edge.
- Random scene at random intervals (2–5 min), random order (no immediate repeat),
  20–40 s duration.
- `purr play` starts a scene immediately, every time — bond/cooldown logic untouched.
- Scene captions on the speech row while a scene runs.
- Zero regressions: idle look identical to v3.7.0; celebrations/birthday unchanged.
- Zero new crate dependencies. Pure-ASCII art only (every char = 1 terminal cell).

## Non-Goals

- No per-life-stage playground art (one stage-agnostic set; rarity color preserves identity).
- No emoji props. No new rows below the statusline. No card changes.
- No `purr play <scene>` picker (declined; may come later).
- No changes to feed/turn hook semantics, LLM react worker, or bond math.

## Architecture Decision

**Deterministic scene engine** (approved; alternatives rejected: persisted per-frame
state machine — 1 locked write/sec forever, lock contention; sidecar playground.json —
second source of truth next to celebrations in state.json).

A scene is *data* (kind, start time, duration, seed) stored in `state.json`. Every
render computes the full picture as a pure function of
`(kind, now − started_at, duration, seed, strip_width, now % 2)`. No per-frame writes.
State writes happen only at scene start and scene end, copying the celebration-tick
pattern: `state::locked_update` on a FRESH state copy with the guard re-checked inside
the closure (statusline.rs:387–402 is the reference implementation; never save the
render-start snapshot).

## 1. Scene Model & State

New enum in `state.rs` (next to `CelebrationKind`):

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, Default, Serialize, Deserialize)]
pub enum PlaygroundScene {
    #[default]
    None,
    Run,            // dash right, pause, dash left, repeat
    Zoomies,        // fast multi-pass with skid stops
    BallChase,      // bouncing ball leads, cat chases, catch at end
    ButterflyChase, // butterfly flutters/bobs, cat follows with lag, pounce finale
    Roll,           // rolls across the strip, sits up, shakes off
    YarnPush,       // pushes yarn ball, trail of ~ fades behind
}
```

New `State` fields, all additive at the end of the struct, all `#[serde(default)]`,
version stays 2 (same pattern as bond/streak fields; add back-compat serde test
mirroring state.rs:353–476):

| Field | Type | Meaning |
|---|---|---|
| `scene_kind` | `PlaygroundScene` | Active scene; `None` = idle |
| `scene_started_at` | `u64` | Unix secs scene began; 0 = never |
| `scene_duration_secs` | `u64` | Rolled 20–40 at scene start |
| `scene_seed` | `u64` | Per-scene RNG seed for trajectory variation |
| `scene_next_at` | `u64` | Unix secs next random scene may start; 0 = unscheduled |
| `scene_last_kind` | `PlaygroundScene` | Kind of the previous scene, for the no-immediate-repeat rule |

All fields initialized in `State::base()`. Scaffolding rule: when matching on
`PlaygroundScene`, write every arm explicitly — no `_ =>` wildcard left behind.

## 2. Scheduler

Lives in `statusline::run()`'s post-compose section (after the celebration tick block).
All three transitions are time-gated, double-checked `locked_update` writes; if the
lock is busy, skip — the next render (1 s later) retries. Renders themselves never
depend on the write succeeding (they compute from the snapshot).

1. **Bootstrap:** `scene_next_at == 0 && scene_kind == None` → set
   `scene_next_at = now + roll(120..=300)`.
2. **Scene end:** `scene_kind != None && now >= scene_started_at + scene_duration_secs`
   → set `scene_last_kind = scene_kind`, `scene_kind = None`,
   `scene_next_at = now + roll(120..=300)`.
3. **Scene start (random):** `scene_kind == None && celebration_kind == None &&
   !is_birthday && scene_next_at != 0 && now >= scene_next_at` → pick
   `kind = roll over {Run, Zoomies, BallChase, ButterflyChase, Roll, YarnPush}`;
   if the roll equals `scene_last_kind`, advance the LCG once and re-roll (a single
   re-roll; a second collision is accepted — this keeps the picker a pure fold over
   the seed). Set `scene_kind = kind`, `scene_started_at = now`,
   `scene_duration_secs = roll(20..=40)`, `scene_seed = lcg(now ^ fnv1a(session_id))`.
4. **Deferral:** while `celebration_kind != None || is_birthday`, transition 3 does not
   fire (scene start waits; an *active* scene keeps its clock running and simply isn't
   drawn — it may expire invisibly; that is acceptable and simple).

**Clock regression guard:** if `now < scene_started_at` (clock moved backwards), treat
the scene as expired (transition 2 semantics) rather than rendering garbage elapsed values.

RNG: the existing dependency-free LCG pattern (`events::roll_random_drop_with_seed`
precedent, events.rs:89–126). `fnv1a` already exists for session hashing.

**`purr play` trigger** (in `hooks::play`, inside its existing `locked_update`):
after `bond::try_play` returns (regardless of `Applied`/`Cooldown`/`InsufficientCoins`),
set `scene_last_kind = scene_kind` (if a scene was active — `purr play` during a scene
restarts with a fresh one), then `scene_kind = roll (no-repeat rule)`,
`scene_started_at = now`, `scene_duration_secs = roll(20..=40)`,
`scene_seed = lcg(now)`, and `scene_next_at = now + roll(120..=300)` (defers the next
random scene so play doesn't double-fire). Bond/coin/cooldown outcomes and printed
messages are unchanged. If a
celebration is currently active, the scene fields are still written — the celebration
finishes first (it has ≤ 12 s budget), and the scene shows for its remaining duration.

## 3. Rendering

New module `rust/src/playground.rs`. Public surface:

```rust
pub struct SceneFrame {
    pub rows: Vec<String>,   // exactly 6 ANSI-colored strings, plain width <= strip_width
    pub caption: &'static str,
}

/// Pure: no I/O, no clock reads. `elapsed` in seconds since scene start,
/// `blink` = (now % 2) for leg/flap alternation. `cat_color` is the ANSI code the
/// caller already computes (rarity_color / shiny cycling), so scenes keep her tint.
pub fn render_scene(
    kind: PlaygroundScene, elapsed: u64, duration: u64, seed: u64,
    strip_width: usize, blink: u8, cat_color: &str,
) -> SceneFrame

/// Reads COLUMNS (set by Claude Code >= v2.1.153 for statusline processes).
/// strip = COLUMNS - 96 (card) - 3 (gap) - 2 (safety), clamped to [24, 120].
/// COLUMNS absent/unparseable -> PURR_PLAYGROUND_WIDTH env override if set,
/// else DEFAULT_STRIP_WIDTH = 60. Returns None if result < 24 (scenes disabled,
/// legacy static rendering).
pub fn strip_width() -> Option<usize>
```

Internals — a tiny compositor keeps the plain/ANSI width convention intact:

- A canvas of 6 rows × `strip_width` cells, each cell `(char, ColorId)`.
- `place(&mut canvas, x, y, lines, color)` blits an actor; clips at strip edges.
- Emission walks each row producing runs: color code emitted only on color change,
  `C_RESET` at row end. Plain width of every emitted row == `strip_width` (space-padded),
  so alignment math never sees ANSI bytes.
- Actors: cat (`cat_color`, so she keeps her rarity/shiny tint), ball `o` (yellow),
  butterfly `}{`/`}i{` (magenta), yarn `@` + trail `~` (pink), skid marks `-` (dim).

Movement math per scene: closed-form over `elapsed` — triangle waves for back-and-forth
runs (`x(t) = tri(t * speed, strip_width - cat_width)`), seed-perturbed phase offsets,
butterfly bob = deterministic pseudo-sine over `elapsed` and `seed`, chase lag = prop
position evaluated at `elapsed - lag`. Endgame beats (catch/pounce) trigger when
`elapsed >= duration - FINALE_SECS` so every scene ends on a story beat. At 1 fps a
cat step of 3–5 cells/frame reads as trotting; Zoomies uses 8–10.

**Integration** in the statusline compose loop (statusline.rs:364–379):

- Scene active AND no celebration/birthday AND `strip_width()` is `Some(w)`:
  rows 0–5 emit `{card_row}   {scene_row_i}` (scene rows replace the 16-col sprite
  column and own the whole strip); row 6 emits the caption via the speech machinery.
- Otherwise: byte-for-byte today's output (home sprite + speech).
- The cat's "home" position (idle) does not move — scenes are the only movement. The
  transition is a cut, not a walk-out (YAGNI; a walk-in can come later).

## 4. Art

New pure-ASCII side-view sprites in `sprites/playground_*.txt`, ≤ 4 rows tall,
≤ 16 chars wide, stage-agnostic:

| Key | Frames | Used by |
|---|---|---|
| `run_right` | 2 | Run, Zoomies, BallChase, ButterflyChase (chase legs alternate) |
| `run_left` | 2 | Run, Zoomies |
| `roll` | 2 | Roll (plus reuse in Zoomies skid) |
| `pounce` | 2 | ButterflyChase, BallChase finales |
| `sit_look` | 2 | scene endings / catch poses (tail flick between frames) |

Loaded via the existing `include_str!` macro pattern into a new
`static PLAYGROUND: &[(&str, u8, &str)]` table in sprites.rs with
`pub fn get_playground_sprite(key: &str, frame: u8) -> Vec<String>` (fallback:
exact → frame 0 → `run_right`@0). New pinned-count test (10 entries); the existing
`SPRITES.len() == 165` / `CELEBRATIONS.len() == 20` pins are untouched. Art rows are
placed on the canvas bottom-aligned (row 5 = ground line).

## 5. Captions

Per-scene `&'static str` pools in `speech.rs` (4–6 lines each), rotated on the existing
30-second bucket formula (`(now / 30) % pool.len()`), e.g. Zoomies: "ZOOMIES!!",
"can't stop won't stop", "the floor is lava"; BallChase: "after it!", "almost...",
"gotcha!!". Finale window (`elapsed >= duration - FINALE_SECS`) may pin the last pool
entry so "gotcha!!" lands with the catch pose.

`SpeechSource` gains a `Scene` variant. Priority: **Celebration > Birthday > Scene >
Quip > Mood** (extend `select_speech_source`, statusline.rs:533–550). Quip consumption
guard (statusline.rs:118) additionally requires `scene_kind == None`, so LLM quips are
not burned invisibly during scenes — same rationale as the existing celebration guard.
Scene caption color: `C_PINK` (matches other overlay sources).

## 6. Degradation, Safety, Config

- **Kill switch:** `PURR_PLAYGROUND=0` (read from the trusted state-dir `.env` or
  process env, like `PURR_DEBUG`) disables scheduler transitions *and* scene rendering;
  active scene fields simply expire.
- **Width override:** `PURR_PLAYGROUND_WIDTH=<n>` forces strip width when COLUMNS is
  absent or wrong (older Claude Code, unusual hosts).
- **No wrapping ever:** every emitted line's plain width ≤ `COLUMNS − 2`; if the strip
  can't fit (< 24 cells), scenes silently don't render. Wrapped lines would shatter the
  7-row layout (confirmed Claude Code behavior: long lines wrap/truncate awkwardly).
- **Lock busy:** any scheduler write skips silently; render is unaffected.
- **Corrupt/old state:** serde defaults make all fields safe; version stays 2.
- **Clock regression:** scene treated as expired; scheduler re-rolls.

## 7. Testing

All via `cargo test` (bin-only crate — no lib.rs; do not create one).

- **Golden frames:** for each scene kind, `render_scene` at fixed
  (elapsed, duration, seed, width, blink) tuples → exact expected strings (start,
  mid-flight, finale). ANSI codes included in goldens.
- **Alignment sweep:** for every kind × elapsed 0..=45 × widths {24, 60, 120}: every
  row's ANSI-stripped width == strip_width; row count == 6; caption non-empty.
- **Scheduler:** bootstrap sets `scene_next_at`; start fires only past `scene_next_at`
  with no celebration/birthday; end clears and reschedules; no-repeat rule holds;
  clock-regression expiry; `PURR_PLAYGROUND=0` freezes transitions.
- **Serde back-compat:** v3.7.0-shaped JSON (no scene fields) loads with defaults.
- **play trigger:** `hooks::play` on `Applied`, `Cooldown`, and `InsufficientCoins` all
  set an active scene; `scene_next_at` deferred.
- **strip_width():** COLUMNS present/absent/garbage; override env; clamp bounds; < 24 → None.
- **Art pins:** PLAYGROUND table count; every playground file ≤ 4 lines, ≤ 16 wide, pure ASCII.

## 8. Release Plan (3 phases, each a fresh ≤ 150k-token session)

1. **Phase 1 — Engine:** state fields + enum, scheduler, `strip_width()`,
   compositor, Run scene using placeholder art (existing front-facing sprite sliding),
   statusline integration, full test scaffold. Visible result: Thalia runs across the strip.
2. **Phase 2 — Art & catalog:** playground sprite set, remaining five scenes,
   captions + `SpeechSource::Scene` + quip guard, golden tests per scene.
3. **Phase 3 — Play trigger & release:** `purr play` integration, kill switch +
   width override, README (user-facing only — no env backdoors beyond documented
   `PURR_PLAYGROUND` toggle), CHANGELOG, version bump to 3.8.0 + Cargo.lock, merge,
   tag, push (Englader auth token), memory update.
