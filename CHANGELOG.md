# Changelog

All notable changes to Purrgotchi are documented here.

Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).
Versioning follows [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Fixed

- **State durability.** `state.json` writes are now fsynced before the rename;
  a crash between rename and data flush could leave a zero-filled file and
  cost the user their kitten. A last-good `state.json.bak` (refreshed at most
  hourly) is restored automatically when `state.json` is corrupt, and corrupt
  files are kept as `state.json.corrupt-<unix_secs>` instead of overwriting
  each other.

### Planned

- Nerd Font icon mode (`PURR_NERD=1` gate)
- macOS builds (built and run on Linux and Windows 11 so far)

  longer stall a prompt (Claude Code's hook timeout is 5 s).

  `~/.claude/settings.json`.

## v3.7.0 — 2026-07-11

Bug-sweep release: a multi-agent audit surfaced 12 confirmed high/medium
defects and 18 minor ones; this release fixes all of them and turns on
per-second sprite animation.

### Added

- **Live sprite animation.** `install.sh` now writes `refreshInterval: 1`
  *inside* the `statusLine` settings object (the pre-v3.7.0 installer wrote it
  at the top level, where Claude Code silently ignores it — the reason sprites
  only moved on tool calls). The sprite frame now flips every second
  (`now % 2`; was every 2s), so the cat visibly animates while the session
  idles.
- **Cross-process state lock.** All `state.json` read-modify-write cycles
  (feed/turn/pet/play/treat hooks, cost accumulator, statusline celebration
  countdown) now serialize through an OS-backed lock file
  (`.purr.lock`, `LockFileEx`/`flock` via `fs2`). Previously four concurrent
  writers raced last-writer-wins, silently losing coins, tool calls, streaks,
  and celebrations, and double-crediting lifetime cost across two windows.
- **Corrupt-state preservation.** An unparseable `state.json` is renamed to
  `state.json.corrupt` before a fresh hatch, so the data stays recoverable.
- **Stale-file sweep.** Orphaned `.*.tmp` atomic-write leftovers (>24h) and
  per-session turn anchors (>12h) are cleaned up once per user prompt.

### Fixed

- **Kitten no longer destroyed by transient file errors.** `load_or_hatch()`
  treated *any* `state.json` read failure — an antivirus briefly locking the
  file, a corrupt write — as "no kitten" and immediately persisted a random
  fresh one. Loads now distinguish missing / unreadable / corrupt: transient
  failures are retried and served from a non-persisted placeholder; only a
  genuinely missing file hatches.
- **Render-counted overlays survive per-second refresh.** Quips now spend one
  of their 6 renders at most every 5s (≥30s visible), celebrations tick at
  most every 2s — instead of burning out in 3–6 seconds under the new refresh.
- **Quips no longer burned invisibly.** The statusline consumed the quip cache
  even while a celebration/birthday overlay outranked it, wasting the LLM call
  without ever displaying the text.
- **ANSI escape injection via LLM quips.** `sanitize_quip` now strips all
  control characters; a prompt-injected escape sequence echoed by the model
  could previously retitle the terminal window or clear the screen through
  the speech bubble.
- **`.env` no longer loaded from the project cwd.** The binary reads secrets
  only from `~/.claude/purrgotchi/.env`; any opened repo's `.env` could
  previously inject `HOME`, provider selection, or API keys into every hook.
  `install.sh` seeds the trusted file from the repo `.env` on first install.
- **Per-turn Cost correct with two windows.** The turn-cost anchor is now
  keyed per session id; a single shared anchor let concurrent sessions zero
  or wildly inflate each other's displayed turn cost.
- **`purr card` bond agrees with statusline/stats.** The card anchored bond
  decay on `last_pet_at` only, showing bond 0 for a cat that was treated
  today but petted a month ago. All three views now use
  `last_interaction_at`.
- **PEAK/OFF-PEAK label off-by-one.** Hour 14–19 is PEAK "2PM-8PM" and the
  off-peak label reads "8PM-2PM"; the old code claimed 2PM-3PM for both
  ranges. Non-Windows `local_hour()` no longer hardcodes UTC+1.
- **Panic fixes.** A single-quote-character LLM blurb no longer panics
  `hatch` (`&trimmed[1..0]`); `purr card` no longer panics on stat/bond
  values >104 (`10 - filled` underflow); `--breed`/`PURR_FORCE_BREED` is
  validated like `--rarity` instead of panicking on unknown breeds.
- **`install.sh` handles paths with spaces** (binary path is now quoted in
  generated commands) and refuses to merge into a malformed `settings.json`
  instead of dying mid-pipeline with a stray temp file.
- **Windows `HOME` confusion.** `paths::home_dir()` prefers `USERPROFILE` on
  Windows so a POSIX-style `HOME` (MSYS2/Cygwin) can't split state into a
  second kitten at `C:\home\...`.
- **Atomic-write temp files no longer leak** when the JSON write itself fails
  (the observed stray `.state.<pid>.tmp`); `debug.log` rotates at 512 KiB;
  the react worker reads only the transcript tail (256 KiB cap) instead of
  the whole file.

## v3.6.3 — 2026-04-28

### Changed

- **Shared LLM transport.** Extracted `ureq` agent construction, `ureq::Error` →
  `LlmProviderError` mapping, error-body truncation, and the connect/read
  timeout constants out of every provider module into
  `rust/src/llm/transport.rs`. Each provider's `complete()` shrinks to a
  single error arm (`Err(e) => Err(transport::map_ureq_error(e))`); the next
  provider takes fewer lines to add. The `Transport` branch is split through
  a pure `map_transport_message(&str)` helper so the timeout/network
  classification is unit-testable without constructing a
  `ureq::Error::Transport`.
- **Error-body truncation now char-based.** `truncate_body` now caps at 500
  characters (was 512 bytes) and no longer appends a `…` marker. Side effect:
  fixes a latent UTF-8 panic risk — the previous byte-indexed truncation
  could split a multi-byte character on a non-ASCII error response. The
  marker carried no observable contract (no caller inspected it), and the
  output is debug-log-only.
- **First-run hint after `hatch`.** When `purrgotchi hatch` succeeds but no
  LLM provider is configured (`PURR_LLM_PROVIDER` unset, or set but the
  matching API key is missing), a one-line hint is now printed to stderr
  pointing the user at `.env`. Statusline / react worker paths remain silent
  — the hint only fires once per kitten lifetime.

### Removed

- **Dead `quip_cache::read`.** A `#[cfg(test)] pub fn` with zero callers;
  deleting eliminates the lone test-profile `dead_code` warning.

### Documentation

- **Watchdog flush contract.** Added a comment in `debug.rs` explaining that
  the file handle is intentionally not wrapped in a `BufWriter` so that the
  v3.6.2 watchdog's "log then `process::exit`" sequence remains flush-safe.
  Prevents a future buffering refactor from silently breaking observability.

## v3.6.2 — 2026-04-28

### Fixed

- **React worker zombie on Windows.** The detached `purrgotchi react` worker
  could hang indefinitely when the underlying HTTP call stalled (TLS handshake,
  slow proxy, provider rate-limiting), because `ureq`'s per-operation timeouts
  do not always fire end-to-end on Windows. The hung process kept an open
  handle on `purrgotchi.exe`, blocking subsequent `cargo build` runs with
  "Access is denied". A 30-second wall-clock watchdog is now installed at the
  top of `react::run`; on expiry it logs `[llm] react fail reason=watchdog_timeout`
  (visible only when `PURR_DEBUG=1`) and force-exits the process with code 0.
  Exit code matches the rest of `react`'s silent-fallback convention.

### Changed

- **Error logging legibility.** `LlmProviderError` now implements `Display`,
  and the `err={e:?}` debug-log lines in `hatch.rs` and `react.rs` switch to
  `err={e}`. HTTP status codes (`HTTP 429: rate limit exceeded`) and error
  messages now surface as one-line summaries in `debug.log` instead of being
  buried in derived-`Debug` formatting. This also resolves the three
  `dead_code` warnings carried since v3.6.0.

## v3.6.1 — 2026-04-28 — Gemini thinking-budget fix

Hotfix for v3.6.0. The default Gemini model (`gemini-2.5-flash`) ships with extended thinking enabled, which silently consumed our entire `max_tokens` budget (50 for react quips, 80 for hatch blurbs) before any visible output was produced. The API returned a candidate with `finishReason: MAX_TOKENS` and no `parts` field; our parser then rejected the response as `MalformedResponse` and the call site fell back to static. Net effect on v3.6.0: Gemini 2.5 looked broken even though the wire calls succeeded.

### Fixed

- `llm::gemini::build_body` now sets `generationConfig.thinkingConfig.thinkingBudget = 0` on every request. Disables extended thinking; safe across the entire Gemini 2.x family (older models silently ignore the field). Tested live against `gemini-2.5-flash` returning clean text responses with normal token usage.
- New regression test `parse_max_tokens_finish_reason_without_parts_is_error` locks in the v3.6.0 failure shape so any future regression here is caught at test time.
- New unit test `build_body_disables_thinking` asserts `thinkingBudget=0` is present in every outgoing request body.

## v3.6.0 — 2026-04-28 — Provider-agnostic LLM (Phase 4)

The LLM layer is no longer Anthropic-only. v3.6.0 ships a pluggable provider abstraction with three impls: Anthropic, Gemini, and OpenAI. A `.env` file is auto-loaded from the current directory so users no longer need to `export` keys per shell.

### Breaking changes

- **`PURR_LLM_PROVIDER` is now required for any LLM feature.** Set it to `anthropic`, `gemini`, or `openai`. Users upgrading from v3.5.0 with only `ANTHROPIC_API_KEY` set will silently fall back to static speech until they add `PURR_LLM_PROVIDER=anthropic` to their environment or `.env`.
- The legacy `crate::llm::call_haiku()` / `HaikuRequest` / `HaikuResponse` / `LlmError` API is gone. Internal callers now use `llm::select::current_provider()` and the `LlmProvider` trait.

### Added

- `LlmProvider` trait with `name()` and `complete(LlmRequest) -> Result<LlmResponse, LlmProviderError>`. `LlmProviderError::Http(code, body)` carries a truncated response body for diagnostics.
- Three provider impls: `llm::anthropic::Anthropic` (default model `claude-haiku-4-5`), `llm::gemini::Gemini` (default `gemini-2.5-flash`), `llm::openai::OpenAi` (default `gpt-4o-mini`).
- `PURR_LLM_MODEL` env var: when set, overrides the active provider's default model.
- `llm::select::current_provider()` reads `PURR_LLM_PROVIDER` (case-insensitive) and dispatches; returns `Box<dyn LlmProvider>`. `ConfigError::ProviderNotSet` and `ConfigError::UnknownProvider(s)` cover the failure modes (both silent at the call site).
- `.env` loader: `dotenvy::dotenv()` runs at the very top of `main()`. Process-set vars take precedence over file values. Missing `.env` is a no-op.
- `.env.example` template at the repo root with all three provider blocks pre-written (commented out).
- Debug log entries now include `provider=<name>` and `model=<model>` fields when `PURR_DEBUG=1` is set.

### Changed

- `react.rs::run_inner` and `hatch.rs::maybe_llm_blurb` both gate on `current_provider()` instead of the old Anthropic-specific `api_key()` check.
- `hooks.rs::maybe_spawn_react` skips the fork when `current_provider()` returns an error (provider unset or unknown). The `*_API_KEY` check still happens inside the worker.

### Cost tracking

`lifetime_cost_usd` continues to track Anthropic-only pricing math; Gemini and OpenAI calls do not contribute to the accumulator. The free Gemini tier means most users on Gemini will see no cost growth, which is correct. Documented as a known limitation; a per-provider pricing model could land in v3.7+.

### Security

- `.env` added to `.gitignore`. The committed `.env.example` is the only `.env` file in version control. Users must `cp .env.example .env` and add their secrets locally.

See `docs/superpowers/plans/2026-04-28-v3.6.0-provider-agnostic-llm.md` for the full implementation plan and rationale.

## v3.5.0 — 2026-04-27 — LLM-powered in-character speech (Phase 3)

The kitten gets an occasional voice. Five items (L1-L5) ship as one bundle.

- **L1 Per-turn LLM reaction.** On `UserPromptSubmit`, the kitten rolls a 1-in-5 die. On hit, a detached `purrgotchi react` worker reads the recent transcript tail (last user prompt + last assistant message + last 5 tool calls), calls Claude Haiku 4.5 with the kitten's identity (name, breed, rarity, peak/dump stats, personality) baked into the system prompt, and writes a one-line quip to a cache file at `~/.claude/purrgotchi/llm-quip.json`.
- **L2 Statusline overlay.** The statusline displays the quip in a pink speech bubble for 6 renders, then reverts to static mood speech. Falls back silently to static when the cache is missing, stale (>5 min), or the API key is absent.
- **L3 API-key gate.** All LLM paths gate on `ANTHROPIC_API_KEY`. Absent → static behaviour; no errors, no prompts.
- **L4 Debug logging.** Every LLM call records latency, input/output token counts, and model in `~/.claude/purrgotchi/debug.log` when `PURR_DEBUG=1` is set.
- **L5 LLM personality blurb at hatch.** When the API key is present, `purrgotchi hatch` calls Haiku synchronously with a "✨ summoning personality…" indicator. All blurbs (LLM and static) now store the literal `{name}` placeholder and substitute at render — fixes the long-standing rename bug where renaming a kitten left the old name baked into the card. Existing kittens with pre-substituted personality strings are not retroactively migrated (substitution is a no-op for them).

Speech-bubble priority: Celebration > Birthday > LLM-quip > Mood.

Architecture: detached cross-platform spawn for the L1 worker (Windows uses `DETACHED_PROCESS | CREATE_NO_WINDOW`, Unix gets default Stdio::null'd spawn); cache file separated from `state.json` to avoid races with the synchronous `feed`/`pet`/`play`/`treat` writers. New dep: `ureq` (blocking HTTP, rustls TLS).

Cost: ~$0.014–$0.056/day at typical usage (10–40 react calls + occasional hatch). Tracked separately from `lifetime_cost_usd`.

See `docs/superpowers/specs/2026-04-27-phase-3-llm-speech-design.md` and `docs/superpowers/plans/2026-04-27-v3.5.0-llm-speech.md`.

## v3.4.8 — D-group events bundle

Five event-driven kitten reactions:

- **D1 Streak** — fires when Claude makes 5 tool calls within a single turn (no `UserPromptSubmit` between). One-shot speech for 3 renders.
- **D2 Milestones** — Centurion (100), Veteran (500), Master (1000), Legendary (every kilo-multiple ≥ 2000). Six-render celebration with milestone-themed speech.
- **D3 Birthday** — day-long ambient mode on the anniversary of `birth_time` (Feb 29 kittens celebrate Feb 28 in non-leap years). Reuses levelup sprite; dedicated birthday speech pool.
- **D4 Daily greeting** — fires on the first `turn()` after a 6+ hour gap. First turn after hatch is suppressed (no welcome-back on day-zero).
- **D5 Random drop** — 0.5% chance per tool call, +10 coins. Coins applied unconditionally even when speech is eclipsed by a higher-priority celebration.

Priority order (highest wins on simultaneous detection): milestone > levelup/evolving > streak > random drop. Birthday ambient mode is overridden by any active celebration.

Three additive state fields with `serde(default)` (no schema-version bump): `streak_count`, `last_milestone_celebrated`, `last_turn_at`. All seven new `CelebrationKind` variants reuse the existing levelup sprite — no new sprite files.

See `docs/superpowers/specs/2026-04-25-d-group-events-design.md` and `docs/superpowers/plans/2026-04-25-v3.4.8-d-group-events.md`.

## [3.4.7] — 2026-04-25

### Added
- **Lifetime cost accumulator.** `state.lifetime_cost_usd` now grows automatically as Claude Code is used while the kitten is around. The `purrgotchi stats` Progress section gained a `Cost: $X.XX` row showing the running total since hatch (or since v3.4.7 install, whichever is later — baseline starts at $0.00).

### Implementation notes
- Accumulation lives in `statusline::run`, which is the only entry point that receives `payload.cost.total_cost_usd`.

- Stale sidecar entries (>30 days) are GC'd lazily on each render.

## [3.4.6] — 2026-04-24

### Added
- **`purrgotchi play` subcommand.** Coin-costing interaction (50 coins, +20 bond, 6 h cooldown, 180 s happy-mood window). Three flavor-text variants rotated deterministically: "pounces on the feather wand" / "chases the laser with frantic joy" / "bats the toy around triumphantly".
- **`purrgotchi treat` subcommand.** Coin-costing hunger reset (25 coins, +5 bond, 4 h cooldown, 120 s happy-mood window). If the kitten was recently fed (< 1 h), coins and cooldown are still consumed and hunger still resets, but the bond gain is skipped and the message flips to a "nibbles it but wasn't hungry" / "sniffs it, eats it anyway" / "accepts politely" variant rotation.
- **`purrgotchi stats` subcommand.** Curated human-readable view of the full kitten state: Identity (name, breed + rarity stars, born, life stage), Stats (five-stat bars with peak/dump annotations), Relationship (effective bond with decay applied, last pet/play/treat timestamps), Progress (tool calls, coins). Read-only — errors loudly if no kitten has been hatched.

### Changed
- **Bond decay now anchors on the most recent interaction of any kind** (pet, play, or treat), not just pet. Previously a user who played daily but never petted would still appear "neglected" for decay purposes. Introduced `bond::last_interaction_at(&State)` as the new anchor.
- **Happy-mood window in `compute_mood`** now OR's three signals (pet, play, treat) against their own window constants. All three converge on the existing `happy` sprite — no new sprite authoring in this release.
- **Shared `format_cooldown(wait_secs)` helper** extracted — all three command cooldown messages now use the same `Xh YYm` formatting.
- **Date rendering helpers unified** — `format_ymd(secs)` lives in `render.rs` as a single source of truth, used by both `card` and `stats`.

### Internal

### Added

### Architecture

- **Source/state separation**: scripts in repo (versioned), `state.json` in `~/.claude/purrgotchi/` (per-machine)
- **Portable path resolution**: `PURR_DIR` computed from `$BASH_SOURCE`, so the repo can live anywhere on disk
- **Performance**: single jq subprocess, bash regex for state parsing, `printf -v` to avoid subshells (Windows process-spawn is expensive)
- **Alignment invariant**: every rendered row has equal visible-char count; verified by ANSI-strip + `awk length`

### Fixed during development

- Bash `IFS=$'\t'` collapses consecutive whitespace tabs (POSIX rule) — switched to `\x01` (SOH) for accurate empty-field preservation
- `$(</dev/stdin)` read was unreliable in CC's Windows spawn context — switched to `$(cat)` for reliability
- Decorative Unicode glyphs (⧖, ◆) have ambiguous east-asian width — removed from content, reserved only for box borders where we control every char
- CRLF injection from jq output on Windows — added non-digit stripping on numeric fields
- `DIR: 0` render bug from empty jq field parsing with wrong IFS — fixed via SOH separator

### Known issues (tracked in `PHASE_2_BACKLOG.md`)

- Windows-format paths (`C:\...`) overflow the box border — no normalization yet
- `TIME` field shows `Xm Ys` even past 60 minutes (no hour unit)
- Debug-log append adds ~700ms latency per render (should be removable now that pipeline is proven)
